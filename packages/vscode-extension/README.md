# DSH ACP Panel

**在 VS Code 里直接使用 DeepSeek Harness。**

无需在编辑器和桌面端之间来回切换：你可以在侧边栏与 DSH 对话，把当前文件或选中的代码带入上下文，查看工具执行过程，切换模型、对话模式与权限，并继续本机已有的历史会话。

面板会优先连接正在运行的 DSH；没有可用连接时，也可以按需启动一套独立的本机配置。会话、记忆和模型设置仍由你自己的 DSH 管理。

顶部“思考”选择器只在内核公布该模型的思考强度选项时出现。模型和思考强度以返回状态为准，当前回合结束后可调整。遇到“不支持该思考强度”时，重新选择后重试；“DSH：诊断配置”可查看当前选择和可用选项。

输入文字和附件草稿保留在本机工作区状态中，恢复期限为 7 天，当前输入与保留草稿合计最多 512 KiB。窗口重载会恢复草稿；消息被后端接收后才清空输入。未被接收的内容留在输入框；执行失败或取消的消息保留在暂停队列中，可取回编辑。多份保留草稿可通过恢复按钮依次切换，现有输入同时保留。恢复不会自动发送。未受信的工作区不恢复附件。

运行中输入下一条消息，按 Enter 或点击“排队”。执行中和等待中的消息合计最多 5 条；已接收的附件使用当时的文本快照。前一条成功结束后按顺序发送；停止、失败、断线、查看历史或关闭面板会暂停剩余消息。点击“继续队列”或“重试并继续”才重新执行。队列属于原对话和目录，切换后需取回编辑再发送。已确认接收的消息独立保存到扩展工作区存储，合计最多 3 MiB、有效期 7 天，不占用 512 KiB 草稿额度。重载后队列一律暂停；目录、信任和原会话通过检查后才可明确继续。重载前已开始执行的消息标记“执行结果待确认”，请核对历史后取回处理，不能直接继续重发。存储失败时输入保留，损坏或过期的恢复记录需明确放弃，系统不会静默丢项。Esc 优先关闭候选或浮层，没有浮层时停止当前回合并保留正在输入的草稿。

“当前未提交变更”范围没有变更时，审查直接结束并注明没有调用模型。审查候选提供方 `0.1.9-ide.8` 默认最多运行 10 分钟或调用 40 次工具；达到预算时保留未完成记录，可缩小变更范围后重新运行。运行中显示检查进度与已用时间。

断线时可查看最近成功查询的只读历史摘要缓存，保留 6 小时，并注明缓存时间、筛选范围和可能已删除的记录。缓存不含完整回放；仅有新版 v4 会话且没有匹配缓存时，会提示连接内核读取。连接恢复后重新查询替换缓存。

审查启动前会列出仓库范围内的未保存文件，可选择只保存这些文件后审查、仅审查磁盘内容或取消。报告分别标记磁盘匹配和未保存编辑；编辑、外部变更、删除与重命名会撤销旧诊断。首次提交前的仓库可审查未提交变更，分支与提交模式仍需有效引用。

当前仅支持桌面版编辑器中的本机文件工作区。Remote SSH、WSL、开发容器、浏览器及虚拟工作区会显示未适配提示；Linux/macOS 的完整发行验收状态与 Windows 分开记录。

## 你可以做什么

- **在侧边栏对话**：发送消息，阅读 Markdown 回复，并实时查看思考内容与工具执行状态。
- **把代码带进对话**：通过编辑器右键菜单附加当前文件或选中的代码，无需手工复制粘贴。
- **切换模型与模式**：直接使用 DSH 提供的模型和 agent preset；选择器显示当前实际模式，待生效模式单独显示，并提供新建对话入口。
- **控制会话权限**：查看并切换当前会话的权限，高风险模式启用前会再次确认。
- **继续历史会话**：只读查看保存在本机的 DSH 会话，选择“继续此对话”恢复上下文，或返回当前对话；恢复失败时输入保持只读。
- **自动连接与恢复**：连接已有 DSH，或按需启动本机 DSH；断线后会在下一次发送时重新连接并尝试恢复会话。
- **审查代码变更**：从源码管理或命令面板启动 Code Review，在 Problems 中定位发现，并打开完整报告。
- **保存审查与验证**：完整报告在本地保存，离线打开历史；把已应用修复、每次测试和后续审查保留在同一记录中。
- **浏览技能**：点击“工具”中的“浏览技能”，搜索并打开技能说明，支持内置技能和文件技能。
- **查看插件运行**：原生运行视图显示审查进度，支持取消和同一内核上的断线恢复。
- **诊断安装与加载**：查看当前连接、配置集版本与来源，以及内核实际注册的能力；复制诊断结果时不包含模型配置和凭据。
- **重新运行与清理**：显式重跑已结束审查，使用新的代码快照；清理旧记录时保留活动任务和已经打开的报告。
- **在原生 Chat 使用 DSH**：输入 `@dsh`，或使用 `/review`、`/skills`、`/new` 和 `/open-panel`。
- **管理文件技能**：从“工具”的更多菜单打开技能管理，编辑草稿、预览差异，再确认新建、更新、启用、删除或恢复。

代码审查、技能浏览与运行恢复需要接入点 `0.5.1` 及已注册 Bridge 能力的适配插件。适配包及其上游来源见 [安装说明](https://github.com/elk-9527/dsh-vscode#bridge-提供方安装)。旧接入点或原版插件下，聊天继续可用。

“工具”视图只保留“审查代码”和“浏览技能”两个直接入口。技能状态通过命令面板中的 **DSH：检查技能状态** 查看，以中文说明呈现加载结果。

## 原生 Chat 与技能管理

原生 Chat 集成在同一个扩展里，使用现有 DSH 模型、配置和连接。稳定版需要 [VS Code 1.91 或更高版本的 Chat API](https://code.visualstudio.com/updates/v1_91)及可用的 Chat 界面。缺少此 API 时继续使用侧栏。`@dsh` 会保存 DSH 会话 metadata，“在 DSH 面板继续”按钮和 `/open-panel` 恢复同一会话，`/new` 开始新对话。取消中止对应请求，权限请求仍需选择 DSH 实际提供的选项。

执行 **DSH：管理技能**。新建或编辑打开未保存的 Markdown 草稿；修改后执行 **DSH：预览并应用技能修改**，查看完整差异并点击“确认应用”。关闭确认不会写入技能。用户技能影响所有项目，确认时显示范围。来源或正文在预览后变化时拒绝提交，需重新预览。

仅当前项目和用户目录下的 `.dsh/skills`、`.agents/skills` 文件技能可修改；系统、运行时、自定义来源和符号链接技能只读。正文上限为 128 KiB，修改使用临时文件与回读核验。原正文保存在技能文件旁的 `.trash`，删除保留其他资源；恢复已删除技能时不覆盖同名文件。编辑不改名，需要另一个名称时新建技能。技能写入要求接入点 `0.2.1`、SDK 及技能试点 `0.4.4-ide.3`，早期候选仍提供只读浏览。

供其他扩展使用的会话、流式提示、能力调用和事件接口见 [公共 API](API.md)。

## 文件引用、历史和修复建议

在输入框旁点击“添加上下文”，选择 **Git 变更** 或 **问题诊断**。可以按文件名筛选，添加当前目录范围或单个文件；附件正文可在发送前预览，并随草稿保存。选择来源不会自动发送消息。

Git 变更分别提供已暂存与未暂存补丁，仅包含已跟踪文件，不含编辑器未保存修改、未跟踪文件和子模块正文；这些内容可另外通过文件或选区添加。问题诊断来自 VS Code 当前已提供的结果，可能来自未保存编辑或尚未更新，不代表执行了测试或完整审查。再次添加可取得新快照；现有附件不会随代码变化而更新。

输入 `/` 时，菜单同时提供命令和技能。命令直接执行，不向模型发送消息；技能选择后成为附件，随下一条消息发送。命令菜单先显示可用操作，再加载技能；工作中的不兼容操作显示为不可用。

| 命令 | 操作 |
| --- | --- |
| `/new` | 新建对话 |
| `/review` | 选择范围并审查代码 |
| `/status` | 查看连接与配置诊断 |
| `/model` | 从内核提供的清单切换模型 |
| `/changes` | 展开本轮改动与测试 |
| `/test` | 选择并运行工作区测试任务 |
| `/help` | 查看快捷引用和命令说明 |

侧栏对话在每轮开始前读取文件基线，结束后列出变化，提供原生差异预览和逐文件撤销。基线保留此前的未提交及未保存内容；列表包含本轮期间发生的编辑，不能据此判定修改者。撤销需要确认，文件在回合结束后变化时拒绝操作。文本恢复进入编辑器，自动保存可能写入磁盘；撤销新建文件会删除它，恢复删除文件会重建它。已有未保存内容与外部磁盘写入冲突时仅提供预览。

快照仅存在于当前窗口内，保留最近 10 轮面板对话，差异正文合计最多 32 MiB；达到上限时淘汰最早记录。旧轮支持差异预览，撤销只适用于最新轮。新对话、成功恢复历史或接入其他会话会清空记录。测试、撤销确认及快照整理期间不能切换会话；会话切换期间不能启动测试或撤销。Git 项目使用跟踪及未忽略文件，其他项目使用工作区文件。每次最多扫描 1000 项，文本单文件最多 256 KiB，总正文最多 16 MiB；跳过链接到外部的文件、二进制、不可读及超限内容。界面注明扫描范围与跳过数量；截断扫描时不提供无法确认的新建和删除记录。公共 API、原生 Chat 和独立审查的编辑不单独生成该快照。

`/test` 仅列出当前工作区中 `group: test` 的 VS Code 任务，请先通过“配置默认测试任务”准备任务。测试使用原生任务事件的实际退出码：0 为通过，非零为失败，无退出码标记未知；取消和启动失败单独标示。测试运行时可停止当前执行；旧执行的取消请求不会停止后来启动的任务。

结束后，结果卡提供“查看此次结果”“附加测试结果”“准备修复草稿”（其他状态显示“准备排查草稿”）和“补充日志”。只读预览显示任务、目录、执行 ID、所属轮次、时间、退出码和变化文件核对范围。原生任务没有可可靠归属的输出读取接口，结果明确显示“未自动取得终端输出”；“打开任务终端视图”打开通用终端视图，不保证定位该执行的专属终端。用户明确复制并粘贴的日志标记为用户提供、未自动核实属于此次执行，最多 128 KiB，控制字符会清理。结束时的编辑器错误诊断单独标示，不能视为失败日志。

查看、附加、补充和准备都不发送消息。准备草稿时保留原正文及全部附件，可通过“恢复保留草稿”切换；检查草稿并由用户发送后才交给 DSH 执行。修复完成后需重新运行所选测试任务。新增证据同样计入 20 项、附件正文合计 256 KiB 和全部保存草稿合计 512 KiB 限制；超限拒绝操作并保留原草稿。

每轮只保留该轮最近一次测试；重跑覆盖或轮次淘汰后，旧执行的操作明确拒绝。预览、附加和准备前重新核对新鲜度。关联轮次已记录的变化文件再次编辑时标记过期，但保留当时真实的通过或失败状态；有未保存内容、没有可跟踪文件或核对不完整时，新鲜度标记为未确认。文件新鲜度仅覆盖本轮已记录变化，不代表整个工作区已经验证。

在 DSH 面板输入框中键入 `@`，按文件名或相对路径搜索当前对话工作区；键入 `/`，按名称或说明选择已加载的技能；键入 `#`，选择当前文件、当前选区或搜索文件。用 ↑↓ 移动、Enter 或 Tab 添加、Esc 关闭。邮箱和 URL 不触发候选。

选中内容显示为可移除的附件，发送消息时才带入对话。文件与选区在加入时保存正文快照，包含未保存修改；之后编辑原文件不会改变待发送内容，再次添加同一项会明确更新快照。技能正文作为本次请求的显式指令传入。技能列表和正文依赖已注册的技能浏览提供方，与“浏览技能”入口使用同一来源。没有匹配项时继续输入以缩小范围。

点击输入框下方的 **添加上下文**，可加入当前全文件、当前选区、搜索文件或选择技能，无需输入快捷语法。**当前文件**与**当前选区**按钮可一步加入；搜索在独立输入框中进行，不覆盖消息正文，也不会自动发送。技能入口只附加技能；**/ 命令**保留命令菜单。Ctrl+Space 打开文件候选；在现有快捷查询中可重新打开已关闭的候选。已打开的工作区文件优先展示。

点击附件名称打开只读正文预览，可核对实际来源路径、全文件或选区范围、加入时的保存状态、快照时间和 UTF-8 字节数。发送使用预览中的正文；关闭预览恢复焦点，Esc 优先关闭浮层。最多附加 20 项，附件正文合计不超过 256 KiB，超限会拒绝新增并保留现有内容，不截断。旧草稿中没有正文的文件链接需移除后重新添加。附件操作需要工作区信任，文件范围以当前对话目录为准；越界的符号链接或 junction 无法引用。手动附件用于指定本次请求的快照，DSH 仍可按任务需要自主读取工作区。

公共 API 保留旧式文件链接兼容：发送本轮文件名、原 URI 及可安全转换的本机路径，提示模型按需调用工具读取。链接本身不包含正文；已有的正文快照继续使用捕获时的内容。

技能服务不可用时，`/` 提供当前项目 `.dsh/skills`、`.agents/skills` 下的文件技能，按目录名或路径搜索。此时仅提供项目技能，服务恢复后可浏览其他已加载来源。

文件及技能引用需要受信任工作区。文件须在当前对话目录内；外部项目及外部符号链接不能引用。最多附加 20 项，正文总量不超过 256 KiB；较大文件请使用 `#` 选择代码片段。选择时仍可修改消息，异步读取不会覆盖新输入或新增的消息文字。

在原生 `@dsh` 中显式引用文本文件或选区时，发送编辑器当前快照，包括未保存修改和未保存文件。引用须属于选定的受信任工作区；重复引用去重，全部引用正文上限为 256 KiB。不同项目的文件需分别发送。`/skills 关键词` 按技能名称和说明筛选。

历史浮层支持按标题、目录或会话 ID 搜索、每页 100 条及“仅当前项目”筛选。搜索覆盖全部历史名片，早于最近 100 条的会话同样可找到。每条记录的“导出”打开保存位置选择框，生成 Markdown，包含可回放的消息、思考和工具记录；原回放有截断时明确标注。搜索和翻页需要接入点 0.3.0。

在 Problems 的 DSH 发现中选择“为此问题生成修复建议”，或在已完成运行的右键菜单选择同名命令。修复使用独立极简会话并核对只读权限，生成期间不批准工具请求。模型返回当前文件的精确替换；原文不唯一、重叠、过大或格式无效时拒绝应用。

选择一项建议后先显示原生差异，再点击“应用此项”。关闭确认保留原文。每项修改进入编辑器，可撤销；保存前不写磁盘。文件、磁盘内容、工作区信任或原审查快照变化时拒绝继续。建议仅在当前窗口保存，十分钟后过期；可用“DSH：预览并逐项应用修复”继续处理，再用“DSH：保存修复并重新审查”保存该文件并建立新的未提交变更审查。

## 保存报告与修复验证

完成审查后，运行记录显示“已保存”才表示完整正文已写入并通过回读。重开窗口后点击记录即可阅读，DSH 停止或原仓库不可访问时仍可查看。历史默认注明“尚未核对当前代码”；执行 **DSH：核对报告与当前代码** 才重新检查磁盘快照和有效位置。Git 分支和提交范围在启动前解析为固定提交；不保存自定义要求或旧权限。

在记录右键菜单选择 **查看修复与验证记录**，查看发现、实际应用的文件替换、测试和后续审查。正文在 VS Code 当前工作区存储中保存，容量为 32 MiB、最多 100 份报告；单份报告最多 1 MiB。打开的报告、关联验证和后续审查正在使用的资料受到保护。空间不足时新报告仍可在当前窗口阅读，清理已结束记录后可重试保存。清理先关闭相关文档并移除引用它的后续审查。损坏的文件不影响其他有效历史。

选择 **DSH：运行修复验证任务**，从原工作区的 `group: test` 任务中选择一次实际执行。修复前可运行发现文件的基线测试；应用修复后先保存文件再重测。验证无需聊天轮次，也不会覆盖另一个对话的测试卡片。当前关联流程支持未提交变更审查；其他审查模式仍可保存和阅读。

每次重测使用新的执行 ID，保留先前失败、取消或未知状态。退出码 0 表示所选任务通过；没有日志不会改变这个退出状态。文件核对仅覆盖发现或实际修复文件，以及可读取的任务配置，不代表全部依赖均被验证。任务范围不证明命令实际工作目录；无法确认时明确标记。运行期间记录文件变化时保留过期状态，历史结果不自动宣称当前代码通过。

普通任务不自动采集终端正文。执行 **DSH：保存或补充验证日志**，选择一次执行，在草稿粘贴最多 128 KiB 的日志，再执行同一命令保存；来源明确标为用户提供、归属未经核实。**将修复与验证记录带入对话** 会先核对原工作区、信任与附件容量，并由用户显式选择发送。后续审查未再次检出原问题，也不能自动证明缺陷已经修复。

已保存修复正文供历史查看；窗口重载后不恢复旧应用批准或可执行的修复计划。

## 安装与运行诊断

从命令面板执行 **DSH：诊断连接与配置**，分别查看磁盘安装清单和当前内核能力。清单引用某个插件不证明插件已经加载；无法确认外部内核所属配置集时，诊断会明确标记“尚未确认”。**DSH：复制连接与配置诊断**复制所显示的元数据，不包含依赖 URL、模型密钥或引导令牌。

**DSH：查看插件安装说明**先选择目标网页配置集，再展示插件、精确版本与来源。只有已确认的注册表来源提供显式安装动作；安装前备份目标配置、锁文件和旧包，安装后回读版本和引用清单。本地候选、Git 和未知来源保留手工说明，未发布的试点候选版本不会生成注册表安装命令。安装后仍需加载内核并刷新能力。

**DSH：重新加载面板后台内核**仅处理扩展启动且空闲的内核；运行任务或聊天工作时不执行。外部内核需在所属应用重新加载。该动作会结束后台内核的空闲会话。

运行记录右键菜单提供 **重新运行审查**和**移除已结束记录**。重试创建新的运行，保留原记录；窗口重开后，自定义要求需重新输入。记录恢复只查询原任务，不会重新调用模型；内核变化、记录过期或工作区变化时显示无法恢复。**DSH：清理已结束记录**保留进行中、取消中和待恢复任务。

已完成且保有完整报告的记录提供 **将审查结果带入对话**，也可从同名命令选择报告。报告附加到现有输入框，可补充问题、查看附件提示中的正文或移除附件；点击发送后才交给模型。报告属于审查时的代码快照，代码变化时会显示提示。此操作需要受信任的同一工作区，超过 256 KiB 的报告需选择部分内容后发送。

当前工作区最多保存 100 条已结束运行的元数据；完整正文另存于本地结果文件，自定义要求不持久保存。清理同时移除允许回收的正文与对应问题提示，打开的报告和正在使用的关联资料保留。界面使用 VS Code 原生树、文字、主题图标和命令入口，支持键盘操作与高对比主题。

当前候选的最低支持版本为 VS Code 1.90.2。侧栏对话、上下文、审查、技能和测试流程不依赖原生 Chat；原生 `@dsh` Chat 的验收基线为 VS Code 1.91.1，并需要可用的 Chat 界面。身份无法确认时限制插件执行，普通聊天与只读诊断保留。当前候选的完整发行验收状态与历史通过记录分别保留。

## 快速开始

### 1. 安装扩展

在 VS Code 扩展市场搜索 **DSH ACP Panel**，或运行：

```sh
code --install-extension Elk-ydy.dsh-acp-panel
```

使用本地 `.vsix` 时：

```sh
code --install-extension <文件路径>.vsix --force
```

安装或更新后，执行一次 **Developer: Reload Window**。

### 2. 准备本机 DSH

请先安装 DSH，并在 DSH 中配置一个可用模型。本扩展还需要 ACP 接入点插件（`dsh-acp-door`）提供本机连接。

安装扩展后，打开命令面板并运行：

> **DSH：准备或修复自启配置**

该命令会创建缺失的 `vscode-panel` web 配置集，安装或更新 ACP 接入点插件，并把桌面端已启用的注册表插件按当前实际版本同步过来。DSH 运行时自带且已在桌面配置集中启用的官方 bundle（例如提供 `auto` 权限的自动授权审查）也会同步。后台启动时还会只读加载 `desktop/cordis.patch.yml`，继承模型路由、插件开关和参数；不会复制或覆盖任一配置文件。已有的同名非 web 配置集不会被覆盖。

也可以手工准备：

```sh
dsh --profile vscode-panel --from-default-profile web --dump-config
dsh plugin --profile vscode-panel add dsh-acp-door
dsh plugin --profile vscode-panel list
```

不要把自启配置集设为 `desktop`：该配置集由桌面端管理，不能由命令行启动。

如果桌面端所用的配置集已经安装 ACP 接入点插件，重启一次桌面端后，面板会优先连接这套正在运行的 DSH。

### 3. 开始对话

点击 VS Code 活动栏中的 DSH 图标，在侧边栏输入问题并按 `Enter` 发送；使用 `Shift+Enter` 换行。

## 两种连接方式

| 场景 | 面板行为 | 需要准备 |
| --- | --- | --- |
| DSH 已在运行 | 直接连接并使用现有内核 | 对应配置集已安装 `dsh-acp-door` |
| DSH 未运行 | 同步桌面端插件后，按需启动 `vscode-panel` 配置集 | 已运行“准备或修复自启配置”，并配置可用模型 |

两种方式都只访问本机 DSH，不提供远程连接或云端同步。

## 常用操作

- 点击面板右上角的 `+` 新建对话。
- 点击时钟图标浏览、回放或接回历史会话。
- 在编辑器中右键，选择 **DSH：把选中的代码带进对话** 或 **DSH：把当前文件带进对话**。
- 使用面板顶栏切换模型、对话模式和权限。
- 在命令面板中搜索 `DSH`，可重新连接、查看日志、准备自启配置或停止面板启动的后台 DSH。

## 设置

打开 VS Code 设置并搜索 `DSH Panel`。

| 设置项 | 默认值 | 用途 |
| --- | --- | --- |
| `dshPanel.autoStart` | `true` | 没有可用连接时，允许面板启动本机 DSH |
| `dshPanel.fallbackProfile` | `vscode-panel` | 面板自行启动时使用的配置集 |
| `dshPanel.dshCommand` | `dsh` | 自动发现失败时使用的 DSH 命令覆盖项 |
| `dshPanel.kernelIdleMinutes` | `10` | 面板关闭后保留自启 DSH 的分钟数 |
| `dshPanel.port` | `47821` | 连接已运行 DSH 的本机端口 |
| `dshPanel.selfStartPort` | `47831` | 面板自行启动 DSH 时使用的本机端口 |
| `dshPanel.provider` / `dshPanel.model` | 空 | 为新会话成对指定初始模型；留空由 DSH 决定 |
| `dshPanel.preset` | 空 | 新对话使用的模式；留空使用 DSH 默认值 |
| `dshPanel.cwd` | 空 | 新会话的工作目录；留空使用当前工作区 |

大多数情况下，只需确认 `fallbackProfile`。扩展会自动查找 DSH Desktop 0.2 的安装目录和随附运行时；只有自动发现失败时才需要填写 `dshCommand`。端口设置通常保持默认即可。

## 本机数据与安全

- 连接仅限 `127.0.0.1` / `localhost`，不支持远程 DSH。
- 普通 ACP 传输没有身份验证；IDE Bridge 插件能力调用使用本机凭据、客户端租约及风险授权。请勿通过端口转发、隧道或局域网暴露接入点。
- 会话、记忆和模型配置由本机 DSH 管理，扩展不提供云端同步。
- 自启配置集与桌面端共用同一份 `$DSH_HOME`。扩展会把桌面端已启用的注册表插件和当前 DSH 运行时自带的官方 bundle 同步到默认的 `vscode-panel`，并在启动时只读叠加 desktop 的模型路由、插件开关与参数；`file:`、Git、URL 等只在原安装现场有效的来源不会自动复制，详情写入 **DSH Panel** 日志。
- 只有主动执行“带进对话”时，当前文件或选区才会作为上下文附加。

## 系统要求

- VS Code 1.90.2 或更高版本；原生 Chat 为可选功能，需要 1.91 或更高版本。
- 本机已安装 DSH，并配置了可用模型。
- 已安装 ACP 接入点插件（`dsh-acp-door`）。
- 兼容 DSH `0.1.5-rc.2`、`0.2.0-rc.1`、`0.2.0-rc.2` 与预览版 `0.2.1-alpha.1`、`0.2.1-rc.2`、`0.2.1-rc.3`；rc.3 需要接入点 `0.6.2`，当前候选的验收状态以兼容矩阵为准。

当前界面语言为中文，暂不支持粘贴图片。完整端到端验证环境为 Windows；其他系统暂未列入已验证兼容性范围。

## 遇到问题

1. 在命令面板运行 **DSH：查看日志**，查看连接或启动失败的原因。
2. 运行 `dsh plugin --profile vscode-panel list`，确认 ACP 接入点插件已经安装。
3. 安装或更新插件后重启对应的 DSH；更新扩展后执行 **Developer: Reload Window**。
4. 运行 **DSH：准备或修复自启配置**，自动创建或修复 `vscode-panel`。
5. 如果自动发现仍然失败，再在 `dshPanel.dshCommand` 中填写完整启动命令。

仍有问题时，请在 [GitHub Issues](https://github.com/elk-9527/dsh-vscode/issues) 提交日志与复现步骤。版本变化请查看[更新记录](CHANGELOG.md)。
