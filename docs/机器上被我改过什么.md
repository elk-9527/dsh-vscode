## 一、DSH 的档（`C:\Users\Lenovo\.dsh\profiles`）

| 时间 | 动了什么 | 怎么撤回 |
|---|---|---|
| 2026-09-19 | `vscode-panel` 档里把门插件 `dsh-acp-door` 从 **0.0.9 → 0.0.11**（`pnpm add file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.11.tgz`） | `node C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile vscode-panel add "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.9.tgz"` |
| 2026-09-19（夜） | 同一个档里把门从 **0.0.11 → 0.0.12**（还是 `file:` 那个 tgz，只是版本换了一个） | 同上，指回 `dsh-acp-door-0.0.11.tgz` |

**为什么非改不可（0.0.11 那次）**：0.0.9 的门只认档里配的端口，不认环境变量。面板自启内核时
要把门钉在 `dshPanel.selfStartPort`（47831），旧门不认，就会去开 47821 ——
那正是你桌面端那个内核的端口，两个抢一个，面板等不到门。0.0.11 先看环境变量。

**为什么又升 0.0.12（2026-09-19 夜）**：面板要加「权限」选择器（跟桌面端那几档同步）。
ACP 协议里没有权限这个东西，只能由门替内核接出来 —— 就是 0.0.12 新加的两个旁路方法
（`dsh-door/permission/get|set`）。**不升它，面板上那个按钮只会说「切不了（门太旧）」。**

**只动了 `vscode-panel`（面板自己的档）**。你的 `desktop` 档、`dshdoor` 档一个字没动。
顺带说清楚一件事：**`desktop` 档里的门还是 0.0.7**，那个档被桌面端独占，
它跑着的时候命令行改不动（`profile "desktop" is managed exclusively by the
Electron application`）。所以桌面端开着、面板连它的时候，权限选择器会显示
「切不了（门太旧）」—— 那时候去桌面端自己的界面上切，效果一样。
想让它也能在面板里切，就等桌面端关掉之后执行一次：

```powershell
node C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile desktop add "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.12.tgz"
```

### 这里出过一回事（记下来，同类别再犯）

我升级门的时候用 PowerShell 的 `Set-Content -Encoding UTF8` 改了门包的
`package.json`，它**悄悄在前面加了 UTF-8 BOM**。打出来的 `dsh-acp-door-0.0.10.tgz`
带着这个 BOM，装进你的档之后：

```
SyntaxError: Unexpected token '﻿', "﻿{ "nam"... is not valid JSON
  at readProfileManifest … at reconcilePlugins …
```

也就是 `dsh plugin` 从此每次都崩 —— **我把你那个档搞坏了**。发现方式是安装命令
退出码不是 0，我顺着 stderr 找到了那个 BOM。

怎么修的：

1. 去掉源文件里的 BOM（用无 BOM 的 UTF-8 重写），**删掉那个坏包**
   `dsh-acp-door-0.0.10.tgz`（它也在我仓库里，已删）；
2. `pnpm` 的 lockfile 里还记着 0.0.10 的完整性哈希，而那个文件已经被我删了 ——
   于是 `pnpm add 0.0.11` 直接报 `ENOENT … 0.0.10.tgz`。**先把 0.0.10 重新打了一份
   干净的**（只为让旧记录能解析），再装 0.0.11，装完把那份临时包删掉；
3. 复核：档里 11 个包一个不少、`dsh plugin --profile vscode-panel list` 退出码 0、
   档里所有 `package.json` 都没有 BOM。

**现在有闸门了**：`node tools/check-eol.cjs` 会报 BOM（退出码非 0），
`test/static.js` 里也有一条断言查装机文件（79 项里那一条）。
**教训：改文件用编辑工具，不要用 PowerShell 写。** 这条也写进了
`docs/交接文档.md` 的"踩过的坑"。
