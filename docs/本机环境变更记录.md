**必须变更的原因（0.0.11 一次）**：0.0.9 版的该插件仅读取档内配置的端口，不读取环境变量。面板自启内核时
需将该插件绑定到 `dshPanel.selfStartPort`（47831），旧版本不支持该绑定，因而占用 47821 ——
该端口正是桌面端内核所在的端口，两者争用同一端口，面板无法等到该插件就绪。0.0.11 版优先读取环境变量。

**再次升级至 0.0.12 的原因（2026-09-19 夜）**：面板需新增「权限」选择器（与桌面端各档保持同步）。
ACP 协议中不包含权限字段，该功能只能由该插件替内核提供 —— 即 0.0.12 新增的两个旁路方法
（`dsh-door/permission/get|set`）。**若不升级，面板上该按钮仅会提示「切不了（门太旧）」。**

**仅修改了 `vscode-panel`（面板自身的档）**。`desktop` 档与 `dshdoor` 档未作任何修改。
另需明确一点：**`desktop` 档内的该插件版本仍为 0.0.7**，该档由桌面端独占，
桌面端运行期间无法通过命令行修改（`profile "desktop" is managed exclusively by the
Electron application`）。因此在桌面端运行且面板连接该桌面端时，权限选择器会显示
「切不了（门太旧）」—— 此时在桌面端自身的界面上切换，效果相同。
若需在面板内同样可以切换，需在桌面端关闭后执行一次：

```powershell
node C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile desktop add "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.12.tgz"
```

### 此处已发生的问题及规避要求

升级该插件时，使用 PowerShell 的 `Set-Content -Encoding UTF8` 修改了该插件包的
`package.json`，该命令**在文件开头自动添加了 UTF-8 BOM**。生成的 `dsh-acp-door-0.0.10.tgz`
带有该 BOM，安装到档之后：

```
SyntaxError: Unexpected token '﻿', "﻿{ "nam"... is not valid JSON
  at readProfileManifest … at reconcilePlugins …
```

即 `dsh plugin` 此后每次均会崩溃 —— **该档已被破坏**。发现方式为安装命令的退出码非 0，
随后依据 stderr 定位到该 BOM。

修复方法：

1. 移除源文件中的 BOM（以无 BOM 的 UTF-8 重新写入），**删除该损坏的包**
   `dsh-acp-door-0.0.10.tgz`（该文件同样位于仓库内，已删除）；
2. `pnpm` 的 lockfile 中仍记录 0.0.10 的完整性哈希，而该文件已被删除 ——
   因此 `pnpm add 0.0.11` 直接报 `ENOENT … 0.0.10.tgz`。**先重新生成一份干净的
   0.0.10**（仅用于解析旧记录），再安装 0.0.11，安装完成后删除该临时包；
3. 复核：档内 11 个包数量完整、`dsh plugin --profile vscode-panel list` 退出码 0、
   档内所有 `package.json` 均无 BOM。

**现已具备检查机制**：`node tools/check-eol.cjs` 会报告 BOM（退出码非 0），
`test/static.js` 中也有一条断言检查装机文件（79 项中的那一条）。
**结论：修改文件应当使用编辑工具，不应当使用 PowerShell 写入。** 该条也已写入
`docs/交接文档.md` 第八节「已发生的问题与规避方法」。
