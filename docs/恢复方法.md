## 情况 A：工作区代码被改乱

先确认改动内容，再决定丢弃范围：

```powershell
cd <仓库根目录>
git status                     # 被改动的文件列表
git log --oneline -10          # workbuddy 的提交记录
git diff v0.1-handoff --stat   # 相对恢复点的改动量
```

三种恢复力度，按由小到大排列：

```powershell
# 1) 只丢弃"尚未提交"的改动（已提交的提交全部保留）
git checkout -- .

# 2) 保留 workbuddy 的提交作为参考，但工作区回到恢复点
git branch workbuddy-试过的东西        # 先为其命名，不应直接丢弃
git reset --hard v0.1-handoff

# 3) 彻底回到恢复点，不参考其改动内容（确认不需要其提交时）
git reset --hard v0.1-handoff
git clean -fd                          # 同时清除其新增的未跟踪文件（会删除文件，确认后再执行）
```

**注意**：`reset --hard` 会丢弃未提交的改动，`git clean -fd` 会删除未跟踪的文件。
执行前应当先通过 `git stash -u` 或 `git branch` 保留名称，不应直接丢弃。

## 情况 B：`.git` 目录丢失（目录被删除或被清空）

使用备份单文件还原（该文件包含全部历史与标签）：

```powershell
# 还原到一个新目录（推荐，不影响现有现场）
$restored = "<仓库根目录>-restored-$(Get-Date -Format yyyyMMdd-HHmmss)"
git clone "<备份根目录>\handoff-20260920-c991b4e\dsh-vscode-all.bundle" $restored
cd $restored
git log --oneline -1        # 预期为 c991b4e
```

还原得到的目录**无需安装任何依赖即可运行测试**：

- 扩展本体：`dependencies` 与 `devDependencies` 均为空（零运行时依赖为刻意设计）；
- 界面测试：直接使用系统中的 `<Chrome 安装目录>\Application\chrome.exe`，
  不使用 puppeteer；
- 该插件：运行时依赖 `@agentclientprotocol/sdk` 已安装在桌面档的 `node_modules` 中，
  与仓库无关。

**唯一需要注意的事项**：仓库根 `node_modules` 有 5 个包（不入库）。如果某个工具报告缺包，
在仓库根执行一次安装即可（先确认所缺的包名，不应盲目安装大量包）。

## 情况 C：安装到 VS Code 的扩展损坏或版本混乱

源码存在时直接重建，该方式最可靠：

```powershell
cd <仓库根目录>\packages\vscode-extension
$panelVersion = node -p "require('./package.json').version"
node tools/build-vsix.js
& "<VS Code 安装目录>\bin\code.cmd" --install-extension "build\dsh-panel-$panelVersion.vsix" --force
# 版本号跟随 package.json，打包脚本按版本号自动命名
# 安装后核对"所装产物与源码一致"（该项目出现过"修改源码后运行的仍是旧版"的情况）：
node tools/check-installed.cjs
```

无需重建时，直接安装备份中的 vsix（按备份日期选择最新的目录）：

```powershell
& "<VS Code 安装目录>\bin\code.cmd" --install-extension "<备份根目录>\handoff-20260919-0944\dsh-panel-0.1.1.vsix" --force
```

安装完成后**必须**执行 VS Code 的 `Developer: Reload Window`（扩展为常驻进程，不重载不生效）。

## 情况 D：面板自身档（`$DSH_HOME\profiles\vscode-panel`）丢失或被改坏

该档**不在仓库中**，于 2026-09-19 在用户机器上创建（面板自行启动内核时使用）。
该档损坏或更换机器时，按以下三条重建 —— 耗时约一分钟：

```powershell
# 1) 从官方 web 模板创建（应当使用 web 模板：ACP 类型的档不接受 --host/--port，ACP 接入点插件（dsh-acp-door）无法开启 TCP 监听）
dsh --profile vscode-panel --from-default-profile web --dump-config | Out-Null

# 2) 安装该插件（版本号跟随 packages/dsh-door 中的 tgz）
dsh plugin --profile vscode-panel add "file:<仓库根目录>/packages/dsh-door/dsh-acp-door-0.0.12.tgz"

# 3) 需要"与桌面端相同的插件集合"时再安装一次（可选；不安装则为干净内核）
dsh plugin --profile vscode-panel add `
  "@anionex/dsh-turn-rewind@0.3.8" "@changfenhuang/dsh-genui@0.11.0" `
  "@linxin666/dsh-client-ui-skin-center@0.3.23" "@liustack/modlens@3.26.1" `
  "@liustack/modsearch@5.10.3" "@tt-a1i/archify-dsh@0.1.0" `
  "dsh-auto-approval-plugin@2.1.2" "dsh-better-sidebar@0.19.1" `
  "dsh-context@0.52.2" "dshmarket@1.47.0"

# 4) 启动一次确认该插件可正常工作（该进程会持续运行，确认后按 Ctrl+C）
dsh --profile vscode-panel --no-open --host 127.0.0.1 --port 0
```

判断"该档能否被面板使用"依据两条：`dsh --profile vscode-panel --help` 中包含
`--host/--no-open/--port`（说明为网页档），`dsh plugin --profile vscode-panel list`
中包含 `dsh-acp-door`（说明已安装该插件）。面板无法启动时也会自行在 `$DSH_HOME/profiles` 中
查找此类档作为备选。

## 情况 E：桌面档（`$DSH_HOME\profiles\desktop`）被改坏

这是**最需要谨慎处理**的一种（其中存放用户正在使用的记忆与插件）。先判断损坏程度：

```powershell
# 查看桌面档的依赖清单（正常应为 11 笔：10 个用户插件 + 1 个 ACP 接入点插件（dsh-acp-door））
type "$env:USERPROFILE\.dsh\profiles\desktop\package.json"

# 与备份进行对照
Compare-Object (Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json") `
               (Get-Content "<备份根目录>\handoff-20260917-1427\desktop-profile-package.json")
```

- **仅撤除该插件**（其余部分均不修改）：
  ```powershell
  dsh plugin --profile desktop remove dsh-acp-door
  ```
- **该插件依赖行被改坏**：将备份中 `desktop-profile-package.json` 内的该行
  `"dsh-acp-door": "file:<仓库根目录>/packages/dsh-door/dsh-acp-door-0.0.7.tgz"`
  按原样写回（**应当使用编辑器或 Node 写入，不应使用 `Set-Content`** —— 该命令会写入 BOM，
  而 DSH 读取带 BOM 的 `package.json` 会解析失败，该故障曾出现过一次）。
- **整个档已混乱**：使用 `<仓库根目录>\backup\desktop-profile-20260917-003620`
  （该插件安装**之前**的快照）对照恢复 `package.json`；`node_modules` 不应整体覆盖
  （体积较大、需要重新安装），只修复 `package.json` 然后重装依赖。
- 恢复完成后**重启桌面端**使插件重新加载。

## 新备份的制作流程

```powershell
cd <仓库根目录>
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
$dir = "<备份根目录>\handoff-$stamp"
New-Item -ItemType Directory -Path $dir -Force | Out-Null

git bundle create "$dir\dsh-vscode-all.bundle" --all           # 包含 .git（最重要的一份）
git archive --format=zip -o "$dir\source-latest.zip" HEAD       # 只含被跟踪的文件，不含 .git
$panelVersion = node -p "require('./packages/vscode-extension/package.json').version"
$doorVersion = node -p "require('./packages/dsh-door/package.json').version"
Copy-Item "packages\vscode-extension\build\dsh-panel-$panelVersion.vsix" "$dir\"
Copy-Item "packages\dsh-door\dsh-acp-door-$doorVersion.tgz" "$dir\"      # 当前发布候选
```
