## 二、路上踩到的三个坑（都写进代码注释与 README 了）

这三件事都不是猜的，每一件都有代码或实测数据为证。

### 坑 1：ACP 这条路从不点名预设，而桌面端把宿主层工具关了

- `dsh-web-app` 的补丁把 `tool-bash` / `tool-pwsh` / `tool-jobs` / `tool-fs` /
  `tool-fs-search` 全部 `disabled: true`，改成「每个会话按 agent preset 挂一套工具」。
- 而 `dsh-acp/lib/index.js` 的 `AcpSession.create` 只传 `meta: { cwd }`，没有预设字段。
- 结果：走门的会话**两头落空** —— 有嘴没手。

内核报错文案指明正道：`(join through AgentPresets.mount() or composeFrom() in the agent factory setup)`。

### 坑 2：`agentPresets` 必须写成**声明式依赖**，不能运行时偷看

cordis 的服务代理对未声明的属性**直接抛**：`cannot get property "agentPresets" without inject`。
而这个异常发生在内核创建 agent 的**同步**流程里，于是：

- 写同步回调 → 异常逃逸 → **`session/new` 直接被打断**（`-32603 Internal error`）；
- 写 async 回调 → 异常变成被吞掉的 promise 拒绝 → 门**假装在工作**（`agentPreset: null`）。

两种都踩过。结论：它进了 `inject`，缺这个服务的 profile 干脆不启动这扇门。

### 坑 3：竞态真实存在，必须用**入站闸**挡住

内核派发 `agent/created` 时**不等待**监听器返回的 promise，所以「补挂预设」与
「客户端发第一个 prompt」是并行的。诊断日志原文：

| 时刻 | 事件 |
|---|---|
| `37.169` | `agent/created` 触发（开始补挂预设） |
| `37.224` | 客户端 prompt 到达（**+55ms**） |
| `37.526` | 预设挂载完成（耗时 **357ms**） |
| `37.527` | 入站闸放行（共压住 **303ms**） |

客户端跑赢了组装，模型收到 **0 个工具 schema**（会话记录 `toolsTokens: 0`），
只能把工具调用当文本写出来（表现为一段 `<｜DSML｜calls>` 文本）。
所以门在传输层把该会话的 `session/prompt` 按住，直到挂载落定。

## 五、复现方法

```powershell
# 1. 打包并装门（必须用 npm pack 产物，不能指向源码目录 —— 见 README 说明）
cd packages\dsh-door
npm pack
dsh plugin --profile dshdoor add "file:<repo>\packages\dsh-door\dsh-acp-door-<版本>.tgz"

# 2. 无界面启动（--no-open 不开浏览器，--port 0 让系统挑空闲端口）
#    想看门内部时序就带上诊断日志环境变量
$env:DSH_ACP_DOOR_DIAG="<repo>\spike\door-diag.log"
dsh --profile dshdoor --no-open --port 0

# 3. 另一个终端：连门验证
node spike/door-probe.mjs
```

产物：`spike/capture/<时间戳>-door.json`、`<时间戳>-door-frames.jsonl`（原始帧）。
