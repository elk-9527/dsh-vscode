# 发布清单

发布对象包括 VS Code 扩展 `dsh-acp-panel`、接入点 `dsh-acp-door` 和提供方 SDK `dsh-ide-bridge-sdk`。版本号以三个包的 `package.json` 为准；最低编辑器来自扩展的 `engines.vscode`，Chat 基线来自 `compat/editors.json`。准备候选前完成版本、CHANGELOG、README 和依赖锁文件修改。

## 三个独立结论

- 普通 CI 通过：代码、行为、类型、公开内容和历史证据结构通过检查，允许当前发行验收为 `pending`。原生 VS Code 完整矩阵由手动任务的 `editor_checks` 按需启用，默认不运行。
- 历史证据有效：已有报告与其当时的版本、平台和必测结果一致；不代表当前源码已验收。
- 当前可以发布：全部声明组合、三个编辑器、本机必测、预检、完整严格回归和真实审查修复工作流均通过，起止指纹稳定，验收文件与发布文件摘要相同。

`compat/versions.json` 和 `compat/editors.json` 的历史记录保留原版本与结果，`currentRelease` 单独记录当前待验收状态。缺少新证据时不更新旧报告的指纹、版本或状态。

## 固定候选文件

```sh
pnpm install --frozen-lockfile
node tools/check-public-paths.cjs
node packages/vscode-extension/tools/check-eol.cjs
node tools/compat/contracts.cjs
node tools/bridge/packages.cjs --out build/candidates
```

输出目录包含唯一 VSIX、接入点 tgz、SDK tgz 和 `manifest.json`。清单记录包版本、平台、产品指纹、测试工具指纹、依赖锁摘要及每个文件的 SHA-256。目录已有同名候选时拒绝覆盖；需要修复源码或依赖时，选择新的候选目录并重新验收。保留被安装配置引用的 `build/install/` 归档。

## 验收这些文件

以下命令中的路径取自候选清单。真实内核、编辑器、配置集与模型测试须使用专用隔离环境；真实模型还需有相应授权。

```sh
node tools/compat/preflight.cjs --out build/compat/preflight.json
node tools/compat/test.cjs --dsh <精确DSH版本> --install --tgz <候选接入点.tgz>
node tools/bridge/test-live.cjs --editor --vsix <候选.vsix> --tgz <候选接入点.tgz> --sdk <候选SDK.tgz>
node tools/bridge/test-regression.cjs --tgz <候选接入点.tgz>
node tools/bridge/test-real.cjs --tgz <候选接入点.tgz> --sdk <候选SDK.tgz>
```

最低支持编辑器、Chat 基线和当前稳定版使用同一 VSIX；相关内核及本机检查使用同一接入点 tgz。SDK 和试点提供方同时记录各自摘要。编辑器流程隔离用户数据、扩展和共享账号目录，检查实际选择变化；主题状态与减少动效配置检查按实际覆盖命名，不当作视觉或读屏证明。

严格回归要求 `DSH_HOME` 指向本项目 `build/` 下的专用目录。提供 `--tgz` 时内核集成测试实际安装该候选，安装失败或内容不同直接失败；不允许拷贝源码补成通过。未提供候选的严格回归仅标记为 `source-regression`，不能作为候选安装证据。

完整严格回归与真实审查修复是两个独立发布门槛。严格回归报告必须记录 `node test/run-all.js --all --strict`、退出码 0、正数套件数和实际 `full-suite.log` 的 SHA-256；日志末尾须有逐项全通过、无重复且计数一致的完整汇总。快速套件通过不能替代它。真实工作流须完成模型审查、只读修复建议、编辑器适配器预览及应用、修复前失败与修复后成功的独立回归、模型复审、离线记录重读、技能健康与内核回收。编辑器适配器结果不构成原生界面证明。

本机验收入口 `tools/compat/local.cjs` 与安装入口 `tools/compat/install-local.cjs` 也要求 `--vsix`、`--tgz`、`--sdk`。本机安装需要单独授权，不能以普通构建或预检代替。各次本机验收通过同一个 `--out` 汇总；安装包或起止指纹不同则拒绝合并。必测失败、跳过、环境缺失或平台不适用均不构成通过；未声明的平台不应新增为必测组合。

隔离本机验收可给 `local.cjs` 指定 `--home <本项目build下的专用目录>`，将配置、临时目录和包管理器缓存一并隔离。`--mode installed --extension-dir <扩展实际安装目录>` 核对指定配置集与扩展安装文件，避免依赖日常安装。编辑器路径可显式指定 `--port`、`--command` 和 `--profile`。同一汇总报告绑定同一配置目录及候选摘要；更换目标应保留旧报告并另建输出文件。

完整日志、配置路径、安装记录和模型输出留在忽略目录。公开证据仅保留版本、平台、摘要、能力与检查结果。审查源码变更、完整暂存内容、提交说明和每张新图片，确认不含私人资料与无依据的结论。

## 生成发布结论

```sh
node tools/compat/release-check.cjs --historical
node tools/compat/release-report.cjs --evidence build/compat/evidence.json --out build/compat/release-report.json
```

`release-check` 只读取与验证已有数据，不运行测试或写报告；`preflight` 负责运行预检，`release-report` 负责保存汇总结论。当前证据使用 schema 2，按产品版本、DSH 版本、发行方式和平台匹配；开始与结束的产品、测试工具、依赖锁三个指纹必须相同，并与当前工作副本一致。任何缺项使结果保持 `pending`、`releaseReady: false`。

`--evidence` 接收 schemaVersion 1 的路径清单，所有引用相对清单文件解析，例如：

```json
{
  "schemaVersion": 1,
  "candidateManifest": "../candidates/manifest.json",
  "kernelReports": ["kernel-a/report.json", "kernel-b/report.json"],
  "editorReports": ["editor-minimum/bridge-report.json", "editor-chat/bridge-report.json", "editor-stable/bridge-report.json"],
  "localReport": "local/local-report.json",
  "preflight": "preflight.json",
  "strictRegression": "strict/regression-report.json",
  "realWorkflow": "real/real-report.json"
}
```

内核数组应列出全部声明组合，不能仅用示例中的两条。编辑器可提供完整原始验收报告或导出的编辑器证据。显式数组覆盖自动登记来源；没有指定的数组读取矩阵 `currentRelease.evidence`。`--report` 仍可补充单个内核报告。汇总区分缺失、过期、失败和格式错误；输出文件已存在时拒绝覆盖。相同产品重新验收可登记新的输入/候选身份，旧证据与历史条目继续保留。

`strictRegression` 与 `realWorkflow` 各引用一份完整原始报告，不接受历史、失败、缺项、跳过或重复必测。两份报告同样须满足 schema 2、平台、三个包版本、起止三指纹和候选摘要要求：严格回归消费最终接入点 tgz，真实工作流消费最终接入点与 SDK tgz。保留报告旁的实际日志与产物；汇总绑定两份原报告，以及严格回归的 `full-suite.log`、真实工作流的 `kernel.log`、`review-report.json`、`repair-suggestion.json`、`regression-1.log`、`regression-2.log` 和 `re-review-report.json`。正式发布入口重新读取原报告、核对这些文件的 SHA-256 并重新验证完整门槛，不能只修改汇总中的 `passed` 或 `releaseReady`。

## 提交已验收的文件

先预演候选校验：

```sh
node packages/vscode-extension/tools/publish.js --candidate <候选.vsix>
node packages/dsh-door/tools/publish.cjs --candidate <候选接入点.tgz>
```

正式上传须由维护者授权，并同时提供完整通过的汇总报告：

```sh
node packages/vscode-extension/tools/publish.js --yes --candidate <候选.vsix> --report build/compat/release-report.json
node packages/dsh-door/tools/publish.cjs --yes --candidate <候选接入点.tgz> --report build/compat/release-report.json
```

正式入口不升版本、不重新打包，拒绝旧格式、错误版本、错误平台、缺失必测或摘要变化。VS Code 市场接收已验收 VSIX 的 `--packagePath`，npm 直接接收已验收 tgz。SDK 发布同样须核对已验收 tgz 及当前报告，不用重新打包的 `npm publish <目录>` 替代。凭据通过环境变量或平台凭据存储提供。

预演和正式路径都检查实际成品内容与 README。公开源码链接指向默认分支 `main` 的存在路径；版本化安装包可使用版本标签或发行附件。发布前确认对应源码路径已合入默认分支。
