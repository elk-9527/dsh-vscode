# 发布清单：两个市场，一条命令

> 日期：2026-09-20　状态：**已准备到「填完占位符、跑一条命令就能发」**。
> 发布要用到的凭据（VS Code 的 PAT、npm 的 token）**不在这个仓库里、也不该进来**，
> 需要你自己在那两个平台注册后填进环境变量。

这个项目要发到**两个互不相干**的市场，两边各有一个包：

| 包 | 发到哪 | 谁审 | 一条命令 |
| --- | --- | --- | --- |
| `dsh-panel`（VS Code 扩展） | VS Code Marketplace | 无人工审核（自动扫描） | `node tools/publish.js --yes` |
| `dsh-acp-door`（DSH 插件） | npm + DSH 插件精选列表 | 维护者读源码 | `node tools/publish.cjs --yes` + 提 PR |

两边都**先彩排**：不加 `--yes` 就是干跑 —— 自检 + 打包 + 把包里的文件列出来给你看，
一个字节都不会发出去。

## 0. 现在卡在哪：三个占位符

三处写的是 `TODO-...`，跑发布脚本会明确拒绝（不是"忘了"，是**不许带着占位符发**：
带着它发布轻则 403，重则发到一个不是你的 publisher 名下，或者市场页面上的链接
全指向别人的仓库）。

| 占位符 | 出现在 | 换成什么 |
| --- | --- | --- |
| `TODO-your-publisher-id` | `packages/vscode-extension/package.json` | 你在 VS Code 市场的 publisher ID（= 你的 Azure DevOps 组织名） |
| `TODO-owner` / `TODO-repo` | 根 `package.json`、两个包的 `package.json`、`README.md` | 你的 GitHub 账号与仓库名 |

一次改完（PowerShell；**用 .NET 写文件，不要用 `Set-Content -Encoding UTF8`** ——
它会加 UTF-8 BOM，门包的 package.json 曾经因此把用户的档搞崩过，事故记录见
`packages/vscode-extension/test/static.js` 里那条 BOM 断言）：

```powershell
cd D:\dsh-vscode
$owner = '你的GitHub账号'
$repo  = '你的仓库名'
$pub   = '你的VSCODE-PUBLISHER-ID'

$files = git ls-files | Where-Object { $_ -match '\.(json|md|yml|yaml|js|cjs|mjs)$' }
foreach ($f in $files) {
  $p = Join-Path (Get-Location) $f
  $t = [IO.File]::ReadAllText($p)
  if ($t -notmatch 'TODO-owner|TODO-repo|TODO-your-publisher-id') { continue }
  $t = $t -replace 'TODO-owner', $owner -replace 'TODO-repo', $repo -replace 'TODO-your-publisher-id', $pub
  [IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))
  "  改写 $f"
}
```

改完自检（两个都应该全 ✅）：

```powershell
node packages/vscode-extension/tools/publish.js     # 彩排：会打到 vsce package 那一步
node packages/dsh-door/tools/publish.cjs            # 彩排：npm pack --dry-run + 打印要提的 PR 内容
```

**仓库要先推上去。** 这个仓库现在还没有 remote，两个市场都要求先有一个公开仓库：

```powershell
git remote add origin https://github.com/<owner>/<repo>.git
git push -u origin main
```

顺带在 GitHub 仓库页面上做两件事：
1. 加 **`dsh-plugin`** topic（DSH 精选列表的硬要求，Settings → Topics）。
2. 确认仓库是 **public**，且创建已 **满 1 天**（CI 会自动查这条：太新的仓库会被当成
   "PR 前几分钟才建好的占位仓库"拒掉；不是对项目的评价，达标了重新提交即可）。

## 1. VS Code 市场（扩展 `dsh-panel`）

### 一次性准备

1. 注册 publisher：<https://marketplace.visualstudio.com/manage> → Create publisher。
   **ID 一旦定下就不能改**，它就是 `package.json` 里的 `publisher`。
2. 生成 Personal Access Token（Azure DevOps → User settings → Personal access tokens）：
   组织选 **All accessible organizations**，权限 **Marketplace → Manage**。
3. 设进环境变量（**别写进任何文件**，这个仓库永远不该出现 token）：

   ```powershell
   $env:VSCE_PAT = '<你的 token>'
   ```

### 发

```powershell
cd packages/vscode-extension
node tools/publish.js              # 彩排：自检 + 打包 + 列出包内文件 + 与自产打包逐文件比对
node tools/publish.js --yes        # 真发
node tools/publish.js --yes --patch  # 顺手把版本号 +0.0.1 再发
```

市场页面几分钟内可见：
`https://marketplace.visualstudio.com/items?itemName=<publisher>.dsh-panel`

### 包里到底装了什么（发布前先看这一眼）

23 个文件，335 KB：`package.json`、`README.md`、`LICENSE`、`CHANGELOG.md`、
`src/**`（11 个 js）、`media/**`（`main.js`/`main.css`/`markdown.js`/`dsh.svg`/
`icon.png`/3 张截图）。

**测试、诊断工具、界面截图工作目录、docs 都不进包**，由两个**互为兜底**的清单管着：

- `tools/ship-list.js` —— 白名单（自产的 `tools/build-vsix.js` 按它打包，本地安装用）；
- `.vscodeignore` —— 黑名单（官方 `vsce` 按它打包，市场用）。

这两个清单**必须一致**，否则会出"本地装的是对的、市场用户装的是缺的"这种只在他
那边才炸的事故。所以 `tools/publish.js` 每次彩排都会把 `vsce ls` 的输出跟白名单
**逐文件比对**，不一致就直接 ❌ 并告诉你差哪几个。

### 市场页面的三样东西

| 东西 | 位置 | 要求 / 注意 |
| --- | --- | --- |
| 图标 | `packages/vscode-extension/media/icon.png` | 128×128 PNG。用 `node tools/make-icon.cjs` 从 `media/dsh.svg` 生成（无头 Chrome 渲染，不额外装图形库）。**不能直接用那个 svg**：它是活动栏图标，单色 + `currentColor`，放到市场页面上等于看不见。 |
| 截图 | `media/screenshots/*.png` | 从 `tools/shots.js` 的产物里挑的 3 张。想换：跑 `node tools/preview.js` 再 `node tools/shots.js`，重新挑。 |
| 说明 | `README.md` | 里面用**相对路径**引图片 —— 市场会按 `package.json` 的 `repository` 字段把它们改写成仓库 raw 地址，所以仓库地址没填对时图片会是一片破图（`publish.js` 有断链检查）。 |

### 版本号规矩

市场**不接受重发同一个版本号**。发布前先决定：

- 改了内容 → `node tools/publish.js --yes --patch`（或手动改 `package.json` 的 `version`）；
- 只改了 README / 截图 → **也得涨版本号**才能更新页面。

### 想撤回

```powershell
npx --yes @vscode/vsce unpublish <publisher>.dsh-panel        # 只下架
npx --yes @vscode/vsce unpublish <publisher>.dsh-panel --force # 连数据一起删（不可逆）
```

## 2. DSH 插件市场（`dsh-acp-door`）

### 先搞清它是什么

DSH 这边的"插件市场"**不是一个上传后台**，而是：① 客户端里的市场插件
（`dsh-market` / `dsh-community-market`）和 ② 目录站 —— 两者读同一份**精选列表**：
[`awesome-dsh-plugin/awesome-dsh-plugin`](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)。

所以"上架"= **发 npm（可选但推荐）+ 给那份列表提一个 PR**。那个 PR 只加**一个文件**。

### 一次性准备

1. npm 账号（<https://www.npmjs.com/signup>），然后 `npm login`。
   已确认 `dsh-acp-door` 这个包名**在 npm 上还没人占**（2026-09-20 查：registry 返回 404）。
2. 让 `package.json` 的 `repository` 指回这个仓库 —— npm 那边的映射是**自动采集**的，
   靠的就是这个字段；指不回去就不会关联到列表条目。

### 发

```powershell
cd packages/dsh-door
node tools/publish.cjs             # 彩排：自检 + npm pack --dry-run + 打印要提的 PR 内容
node tools/publish.cjs --yes       # 真发 npm
```

包内只有 10 个文件、35 KB：`package.json`、`README.md`、`CHANGELOG.md`、`LICENSE`、
`cordis.patch.yml`、`lib/*.js` 五个。测试、`tools/`、`assets/`（截图）、`*.tgz` 都不进包
（`files` 字段管着）。

### 提 PR（一个文件就是全部投稿）

脚本会把内容打印给你，直接抄进 `data/plugins/<owner>__<repo>--packages-dsh-door.yml`：

```yaml
url: https://github.com/<owner>/<repo>/tree/main/packages/dsh-door
name: <owner>/<repo>#dsh-door
category: dev
description:
  en: 'Loopback-only ACP door for DeepSeek Harness: attach an external client (such as the DSH Panel VS Code extension) to the kernel you already have running, exposing session listing and permission presets.'
  zh: 给正在运行的 DeepSeek Harness 内核多开一扇只监听本机的 ACP 门，让外部客户端（如 VS Code 的 DSH 面板）接上同一个内核，并接出会话列表与权限预设。
```

规则（来自上游 `contributing.md`，2026-09-20 逐条核对过）：

- 文件名 = `<owner>__<repo>.yml`；monorepo 子包在仓库名后面接 `--` 和子目录名
  （`packages/dsh-door` → `--packages-dsh-door`）✓ 脚本按这个规则生成。
- 条目里 `name` 的 `#dsh-door` 是**子目录名**（照上游的规则填："subname 就是子包路径"）。
  注意子目录叫 `dsh-door`、而包名叫 `dsh-acp-door` —— **用户安装时用的是包名**
  （`dsh plugin add dsh-acp-door`），这两者不一致是正常的，不是填错了。
- `description.en` 里**含 ": " 必须加引号** —— 我们的英文描述正好含（"Harness: attach …"），
  脚本已经写成单引号了，抄的时候别把引号去掉。`zh` 可选（不写维护者会补）。
- `category` 只能取这些值：
  `agi` `ui` `usage` `theme` `model` `identity` `session` `memory` `tools` `wsl` `browser`
  `vision` `voice` `docs` `skill` `workflow` `git` `notify` `dev` `security` `remote` `market` `fun`。
  我们选 **`dev`**（它本质是开发/集成用的传输层）。选不准没关系 —— 说明里写了
  "没人会因为分类被打回，维护者直接改"。
- **不要手工编辑他们那两个 README**，它们由脚本从 `data/plugins/*.yml` 生成。
- 一个 PR **最多 3 条**。
- 描述**必须属实**（维护者会对着代码读）：我们写的是"只监听本机、会话列表与权限预设"，
  跟实现一致 ✓。这也意味着**别加营销词**。
- 硬要求：仓库声明了 `dsh.bundle`（我们是 `dsh.bundle.patch` ✓，在
  `packages/dsh-door/package.json`，旁边的 `cordis.patch.yml` 也在 ✓）、有真实代码、
  仓库满 1 天、有 `dsh-plugin` topic。
- 官方 `@deepseek-ai/*` 包要用 `peerDependencies` 而不是 `dependencies`：
  我们只依赖 `@agentclientprotocol/sdk`（第三方），不涉及这条 ✓。
- npm 映射**不需要在 yml 里写任何字段**：手写 `npm:` 键会被校验**拒绝**。

### 截图（可选，推荐）

市场的详情页能像 App Store 那样展示截图。上游现在要求**把清单放在自己的仓库里**：
`packages/dsh-door/screenshots.json`（紧跟 `package.json`），列 1–8 张、路径相对该文件：

```json
["assets/panel-chat.png", "assets/panel-permission.png"]
```

为什么不用绝对 URL：写死在他们那边的地址只会悄悄烂掉（上游说已发布的 773 张里
41 张就这么 404 了），而相对路径在自己仓库里改名立刻可见。也接受绝对 URL，但必须
是 GitHub 托管的 https，且路径不能跳出本包目录 —— `tools/publish.cjs` 每次都会校验。

### 不发 npm 也行（备选）

如果不想发 npm，就把打好的 tgz 挂到 GitHub Release，然后在条目里加一行
`tarball: https://github.com/<owner>/<repo>/releases/latest/download/dsh-acp-door.tgz`。
**注意**：`latest/download/` 只在请求时解析 `latest`、文件名是照字面取的 ——
文件名里带版本号的话，发下一版就会 404。要么文件名不带版本号，要么钉住 tag
（`.../releases/download/v0.0.12/dsh-acp-door-0.0.12.tgz`）。

### 想撤回

- npm 上发布 **72 小时内**可以 `npm unpublish dsh-acp-door@<版本> --force`，之后只能
  `npm deprecate`（改发新版本修问题）。
- 列表条目：给 `awesome-dsh-plugin` 提一个删掉自己那个 yml 的 PR。

## 4. 隐私 / 安全（发布前值得再看一眼）

- **`docs/*.md` 里有这台机器的绝对路径**（`D:\dsh-vscode`、`C:\Users\Lenovo\...`、
  备份目录名）。这些文件**不进任何发布包**（两个包的白名单里都没有 `docs/`），
  但它们会跟仓库一起公开 —— 这是工作记录，公开发布前你可以选择是否要留。
  同样情况还有 `spike/`（早期探针脚本）和 `packages/*/tools/`。
- 门**只监听 `127.0.0.1`、没有鉴权**。这是刻意的（本机自用），但意味着**同一台机器上的
  任何程序**都能连上来驱动你的 DSH。已经在两个 README 里写明，别改成 `0.0.0.0`。
- 仓库里**没有**任何 token / cookie / 会话内容：`*.tgz`、`backup/`、`shots/`、
  `spike/scratch/`、`.workbuddy/`、会话勘察报告都在 `.gitignore` 里（`backup/` 是
  2026-09-19 才发现管不住已跟踪文件的，已经 `git rm --cached` 摘出来了）。
