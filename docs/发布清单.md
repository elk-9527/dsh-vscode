# 发布

本项目包含 VS Code 扩展 `dsh-acp-panel`、DSH 插件 `dsh-acp-door` 以及提供方 SDK `dsh-ide-bridge-sdk`。

## 验证

```sh
pnpm install --frozen-lockfile
node tools/check-public-paths.cjs
node packages/vscode-extension/test/run-all.js --all --strict
node packages/vscode-extension/tools/check-eol.cjs
```

确认版本号、CHANGELOG、项目文档与待发布代码一致，并验证实际安装包。

## 安装包与预检

```sh
node packages/vscode-extension/tools/build-vsix.js
node packages/vscode-extension/tools/publish.js
cd packages/dsh-door
node tools/publish.cjs
```

两个发布脚本默认只执行预检。市场发布需显式指定 `--yes`。
发布凭据通过环境变量或平台的凭据存储提供。

SDK 发布前，运行其契约和类型检查、独立示例及两个试点的真实 Bridge 验收，再执行 `npm pack --dry-run` 检查发行内容。SDK 和上游试点的发布状态分别核对；本地候选安装不代表 npm 可用。主扩展 0.15.0 要求 VS Code 1.141.0；最低版本和当前稳定版都须验收同一份最终安装包。运行 `node tools/bridge/test-live.cjs --editor --packed-vsix` 验证已构建包的引用、历史导出及修复流程；未提供 `--packed-vsix` 时重新构建。公开编辑器验证结果只保留版本、检查名称与状态，完整日志和安装路径留在本机。

发布前核对每份证据的产品源码指纹和实际安装包 SHA-256。兼容工作流只构建一次候选 VSIX，两个编辑器任务下载并核对同一摘要。完整回归和真实模型验收分别执行 `node tools/bridge/test-regression.cjs` 与 `node tools/bridge/test-real.cjs`；外部模型适配器通过 `DSH_PANEL_TEST_PROVIDER_PACKAGE` 显式选择，只安装到专用测试配置集。任一必测失败、跳过或缺少对应版本证据时保持候选状态。

CI 候选包使用固定的 `@vscode/vsce@4.0.0` 生成，并与本地打包白名单逐项比较。向 VS Code 市场提交该候选时，使用 `npx --yes @vscode/vsce@4.0.0 publish --packagePath <已验收的VSIX路径>`，保持发布文件与两个原生编辑器验收的摘要一致；重新打包后须重新核对安装包证据。
