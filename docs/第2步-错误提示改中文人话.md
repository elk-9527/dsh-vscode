# 第 2 步：把内核的报错改成中文人话（已完成）

日期：2026-09-17（接手后的第一件事）
改动前的提交：`2c45d17`

## 为什么要做

内核的报错是**原样**穿过 ACP 传到面板的。用户看到的是一段英文 JSON：

```
回合失败：Internal error: turn failed: 429: {"type":"GoUsageLimitError",
"message":"5-hour usage limit reached. Resets in 12min..."}
```

这段文字对用户没有用 —— 既没说发生了什么，也没说下一步该干什么。
最直接的后果是额度用完时用户以为「插件完全没法用」。

### 认得出哪几类

额度/频率限制（429、`GoUsageLimitError`、限流、余额不足）、鉴权失败（401/403、
`Incorrect API key`）、端口被占（`EADDRINUSE`）、命令不存在（`ENOENT`、
`不是内部或外部命令`）、连不上内核（`ECONNREFUSED`/`ECONNRESET`/断线）、
预设被锁（`agent-preset/locked`）、模型名不认识、超时。

两条不能破的规矩：

1. **不吞信息** —— 原文永远跟在人话后面一起给用户（认不出来时更是如此，
   `.err-raw` 里一字不删）；
2. **不猜** —— 只按能明确指认的特征分类。认不出来就老实说「认不出来」
   （`.err-title` 是「DSH 内核报了一个错」），而不是硬套一个类别把用户带错方向。

认得出时额外做了两件小事：429 会从原文里抠出「还有多久恢复」（`Resets in 12min`
→「大约 12 分钟后额度恢复」）；端口被占会把端口号带进建议里。

## 顺手修掉的那个真 bug：`dshCommand` 带参数时起不来

**症状**：`dshPanel.dshCommand` 填 `node D:\...\dsh\lib\bin.js`（本机 `dsh` 不在
PATH 上时就得这么写），兜底拉起一定失败，日志里是「后台 DSH 退出了（code=1）」。

**根因**：`locate.js` 把**整串**命令当一个程序名加引号：

```
cmd.exe /d /s /c ""…/node.exe …/bin.js" --profile dshdoor …"
                            ↑ cmd 去找一个名字里带空格的程序
```

实测（`cmd.exe /d /s /c`，两种写法对比）：

| 写法 | 退出码 | 输出 |
| --- | --- | --- |
| `"…/node.exe …/bin.js" --version`（改之前） | 1 | `是内部或外部命令…` |
| `…/node.exe …/bin.js --version`（改之后） | 0 | `0.1.5-rc.2` |

**修法**：新增纯函数 `splitCommand()` + `commandLine()`：先按空白把命令拆成
「程序 + 它自带的参数」（支持用引号把带空格的整段括起来），再逐段加引号。
`spawnBackgroundDsh` 和 `runDshSync` 都改走它。命令填成空的时候立刻抛错，
不再拖到进程起来之后。

**这条为什么重要**：本机 `dsh` 命令**不在 PATH 上**（npm / pnpm / nvm 的 bin
目录里都没有 `dsh.cmd`），唯一的 CLI 是
`C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js`。
所以「把 dshCommand 指到 bin.js」这条路能不能走通，全看这个修复。

新增断言：

- `test/panel.js` 的 **8.7**：5 类错误各断言四件事（分类对、说清了发生了什么、
  说清了能做什么、原文一字没少）；认不出来的错误也要有人话开头且保留原文；
  再从会话层真的 `emit('error')` 一次，断言面板发出去的确实是「人话 + 原文」。
- `test/panel.js` 的 **8.8**：`splitCommand` / `commandLine` 的拆解与引号行为。
- `tools/uitest.js` 的 **error 场景**（预览页里的 `human` 是**真的调一次**
  `src/dsh/errors.js` 算出来的，不是手抄的）：断言人话在前、原文还在、
  人话里没有 JSON、原文块可换行、人话对比度 9.54:1。
