## 原始参考（实测现状，改动前后均适用）

### 约束：跟随 VS Code 主题

面板位于 VS Code 侧边栏内，与编辑器相邻。因此颜色**一律使用主题变量**
（`--vscode-*`），不自行固定颜色 —— 否则更换主题后，面板配色将与主题不一致。
该约束当前已满足：审计过 404 条 CSS 声明，**硬编码颜色 0 处**，使用了 32 个主题变量。

因此颜色不是主要问题；**主要问题是尺寸尺度**。

## 实测现状（`node tools/design-audit.js`，可随时复跑）

| 项 | 现状 | 问题 |
| --- | --- | --- |
| 间距值 | 10 种：1 / 2 / 3 / 4 / 5 / 6 / 8 / 10 / 12 / 20 px | 6 种不在 4px 尺度上，属随意取值 |
| 字号 | **13 种**：0.82 / 0.85 / 0.9 / 0.92 / 0.94 / 0.95 / 1.05 em，10 / 11 / 13 px，1em，inherit，主题字号 | 0.9/0.92/0.94/0.95 取值相互接近，等同于"未建立层级" |
| 行高 | 5 种：1 / 1.45 / 1.5 / 1.55 / 1.6 | 1.45/1.5/1.55/1.6 之间的差别无法目视区分 |
| 圆角 | 4 种：2 / 3 / 4 / 999px | 该组取值合理（层级 + 胶囊） |

**外观一致性不足的根源即在上表中**：并非颜色不正确，而是尺寸未收敛到统一尺度 ——
13 种字号意味着每个元素均单独调整过一次，尺寸取值缺乏统一尺度。
另外：仅使用过一次的间距值为 1px / 5px / 20px，这类取值多属于个别场景下的临时添加。

## 原提案（用户默认认可：不修改配色与布局结构，仅收敛尺度）

不修改配色与布局结构，仅收敛尺寸尺度：

- **字号收敛为 4 档**（当前 13 种）：正文（跟随主题字号）、次要信息（0.92em）、
  标题（1.05em）、代码（0.9em 等宽）。层级通过**字重**区分，不通过增加字号档位实现。
- **间距收敛到 4px 尺度**（4 / 8 / 12 / 20）：1px、2px、3px 仅用于描边与
  行内微调；5px、6px、10px 归入 4 或 8。
- **行高收敛为 2 档**：正文 1.55、紧凑处（卡片标题、状态行）1.35。

预期效果：元素之间呈现明确关联，而非各自独立。改动后 `design-audit` 的
数值将直接反映收敛结果，`tools/shots.js` 亦可提供前后对比图。

## 原 6 问原文（存档备查，答案见文首表格）

1. **品牌感的取舍**：面板是否应当具备自身的识别度（例如顶栏一条细的强调色，
   或某一位置固定的强调色），或者完全交由主题处理、不添加任何自有颜色。
   —— 这一项是"外观上接近 VS Code 内置功能"与"外观上接近具备独立标识的工具"的分界。
2. **消息形态**：当前为用户与助手两侧分栏的对话形态。选择更接近聊天的形态（含气泡、含头像），
   或者更接近"文档流"的形态（即当前形态：助手输出即正文，工具调用为折叠卡片）。
3. **工具调用的显示**：当前为多张卡片、默认展开。是否改为默认折叠为一行
   （"读取 3 个文件 ▸"），点击后展开。对话较长时该差别较为明显。
4. **密度**：取决于个人偏好 —— 选择"单屏显示更多内容"（紧凑），或者"留白更多"（松弛）。
5. **动效**：是否添加少量克制动效（新消息淡入、工具卡片展开与收起带过渡）。
   当前基本没有动效。
6. **信息的取舍**：当前顶栏为模型 + 上下文用量，右上角为新建/重连。是否添加时间戳、
   花费/耗时、当前工作目录，或者保持界面信息量最小。

改动顺序：先确定尺度 → 再确定形态 → 最后处理每处细节；每一步均截图，结果不满足预期则回退。

## 改动的验证方式

- `node tools/design-audit.js`：字号/间距/行高/圆角的种类数（应当明显下降）。
  添加 `--strict` 时，存在硬编码颜色则以非 0 退出（用户已确认：配色完全跟随 VS Code 主题，
  不自带强调色）。
- `node tools/shots.js`：18 张图（9 个场景 × 深/浅主题）的改动前后对比。
- `node tools/uitest.js`：494 项界面断言必须仍然全部通过（文字不截断、按钮可点击、
  浮层不越界、间距一致、对比度足够）；该脚本同时断言**计算后的样式**（而非"class 是否存在"）——
  该断言源于曾出现的问题：class 存在但规则被覆盖，界面显示仍然不正确。
