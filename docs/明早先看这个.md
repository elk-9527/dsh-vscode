# 明早先看这个

## 一句话

VS Code 侧边栏里的 DSH 面板：**做好了、装好了、测过了**。
打开 VS Code，点左边活动栏里那个 DSH 图标，就能直接跟你的 DSH 说话。

## 早上照着做（三步，约 2 分钟）

1. **重启一次 DSH 桌面端。** 门插件是在进程启动时加载的，你昨晚开着的那个进程
   还不知道门的存在。（不重启也能用，见下面"两种情况"。）
2. **在 VS Code 里按 `Ctrl+Shift+P` → `Developer: Reload Window`。**
   这个必须做：我重装扩展的时候你的窗口正开着，它现在加载的还是旧版。
3. 点活动栏里的 DSH 图标，发一句话（比如"你记得我今天问过什么吗"）。

应该看到：状态点变绿写"已连上"；上面有模型下拉/用量条；回答一个字一个字出来；
用工具时出现工具卡片；在编辑器里选中几行 → 右键 → `DSH：把选中的代码带进对话`，
输入框上面会出现一小块，点 × 能拿掉。

**验收清单**（每条都该是"就是这样"）：

| 该看到什么 | 怎么看 |
| --- | --- |
| 面板连上了 | 顶部状态点绿色，写"已连上"，不是"正在连接…" |
| 连的是桌面端那一个进程 | 先开桌面端再开面板时，任务管理器里**不该多出**一个 dsh 进程 |
| 记忆是同一份 | 问它一件你以前跟它说过的事，它答得出来 |
| 流式输出 | 回答逐字出现，不是憋一大段后突然全出来 |
| 工具卡片 | 让它读个文件，卡片出现并变成完成态 |
| 编辑器上下文 | 右键带进来的东西显示成小块，发出去后气泡里还留着 |
| 模式切换 | 顶栏模式下拉换一个 → 状态里会说"下一段新对话用它" |
| 断线自动接回 | 重启桌面端后接着发消息，它会自动接回原来那段对话 |
| 日志 | `Ctrl+Shift+P` → `DSH：显示日志`，每一步都有记录 |

如果第 3 步看到的是空面板或者一直"正在连接…"：先看日志（`DSH：显示日志`），
再把日志里那几行发我。

## 建议的操作顺序（这个顺序最理想）

1. **先开 DSH 桌面端**（等它起来）；
2. **再开 VS Code**，点侧边栏的 DSH 图标。

这样面板连的就是你桌面端**正在跑的那一个进程**：一个进程、一个大脑、
同一份记忆、同一份会话记录。这也是你当初选的方案。

如果你反过来（先开 VS Code）：面板会发现桌面端没开门，于是**自己拉一个后台内核**，
用的还是 `desktop` 这个档 —— 记忆、技能、插件完全一样，只是多了一个进程。
两种情况都能用，第一种更干净。

> 为什么先开桌面端才有效：门插件是在**进程启动时**加载的。
> 我今晚把门装进了 desktop 档，但你此刻正在跑的那个桌面端进程是装之前起来的，
> 它还不知道门的存在。**重启一次桌面端（或重启电脑）就到位了。**

## 它到底是什么

就是我桌面上已经配置好的那一个 dsh，不是另起一个 agent。

证据（都是实测）：

- 面板连的那个内核，组合出来的插件树里有你自己那 **11 个插件**
  （记忆 hindsight、genui、modlens、modsearch、archify、skin-center、
  dshmarket、better-sidebar、dsh-context、auto-approval、turn-rewind），
  加上门本身，一共 12 个依赖 —— 逐个核对过，一个没少。
- 会话的工作目录就是你打开的那个文件夹。
- 记忆和会话数据在 `$DSH_HOME`（`C:\Users\Lenovo\.dsh`）这一层，
  是所有档共用的一份，没有复制、没有另建。

## 这一夜做了什么

**门插件 `dsh-acp-door`**（`packages/dsh-door`）
在你的 DSH 内核上多开一扇只监听本机的 ACP 门（`127.0.0.1:47821`），
这样外部程序才能接上一个**已经在跑**的 DSH。
另外它要替 ACP 会话补挂 agent preset —— 桌面端架构把宿主层工具全关了、
改成每个会话按预设挂，而 ACP 这条路从不点名预设。

**面板扩展 `dsh-panel`**（`packages/vscode-extension`）
活动栏图标 + 侧边栏聊天面板：流式输出、Markdown 渲染、工具调用卡片、
代码改动 diff、上下文用量条、模型切换、**模式（agent preset）切换**、
中断、权限确认、断线重连、**接回上一段对话**、
**编辑器上下文**（在编辑器里右键就能把当前文件或选中的代码带进对话）。

**测试 11 个套件、全绿**，一条命令跑完（`node test/run-all.js --all`，约 3 分钟）：
静态契约 41 / 门的看帧判断 71 / Markdown 渲染器 34 / 编辑器上下文拼块 42 /
会话层边界 27 / 真浏览器界面 283（7 个场景）/ 兜底拉起 9 / 断线接回 5 /
预设模式 39 / 面板层 50 / 端到端真 DSH 31。合计 **632 项断言**。

界面还能**拍下来看**：`node tools/shots.js` 会把每个场景 × 深/浅主题拍成
`shots/*.png`，改界面前后各拍一次就能对比。

另外还有一条**独立于上面这些**的证据：`node tools/vscode-check.js`
会在**真 VS Code 窗口**里跑一遍（开一个隔离窗口，自己的 user-data-dir 和
extensions-dir，不碰你正开着的窗口），断言 11 条：窗口起来 → 扩展激活 →
五个命令注册 → 视图进活动栏 → 面板自动展开 → ACP 握手 → 建出会话 →
兜底拉起的是 desktop 档 → 收摊干净 → 不留孤儿内核 → 你自己的窗口没被动。
约 30 秒，跑完自动收摊，全绿。

**修掉的真 bug**：

1. Markdown 渲染器遇到「以 ``` 开头但不是合法围栏」的行会**死循环把内存吃光**
   —— 在 webview 里就是把整个面板冻死。模型吐出残缺代码块就会触发。
2. 渲染只依赖 `requestAnimationFrame`，而面板被折叠/隐藏时浏览器会**完全停掉 rAF**
   —— 后台跑完的回合会一直不显示，直到你把面板重新切出来。
3. **断线接回之后，会话的手没了。** 这个是今晚抓到的，也是最严重的一个：
   同一个会话，断线前 18 次工具调用，接回来 **0 次** —— 模型开始把工具调用
   当文本写出来（`<｜｜DSML｜｜invoke …>`），因为它手里一个工具 schema 都没有。
   根因：内核只在"桌面端那种建会话方式"下把预设写进会话记录，走门的会话记录里
   没有这个字段，恢复时内核重建出来的 agent 就是个空壳；而"切换预设"的接口
   对跑过回合的会话是锁着的。修法：撞锁就改用工厂期那个 `mount()` 补挂，
   门另在本进程里记一份「哪个会话用哪个模式」。
4. **界面上的空控件其实一直在那儿**：模型下拉、用量条、黄色权限框都用 `hidden`
   藏，但 `[hidden]` 是浏览器默认样式、优先级最低，被组件自己的 `display:flex`
   盖掉了 —— 也就是你刚打开面板时会看到一行空下拉、一条空进度条、一个空权限框。
   现在加了全局 `[hidden]{display:none !important}`，并且每加一个控件都有一条
   「该藏的必须真藏住」的断言盯着（`bare` 场景）。

**三处加固**：Windows 上收摊改用 `taskkill /T` 杀整棵进程树（不然真正的内核会
变成孤儿进程一直在后台占内存）；自动拉起内核时不再用 `shell:true` 拼参数
（profile 名来自设置项，那是个注入点）；兜底内核对外的网页界面锁死在回环地址。

**第 1 步：把门装进你的 desktop 档**（原计划放到最后的那一步）。
改了什么、备份在哪、怎么卸，都写在 `docs\第1步-装进桌面端.md` 里。
门现在是 **0.0.7**（带上模式切换和那个"接回来没有工具"的修复）。

## 编辑器上下文怎么用

你在写代码时想让我看一眼某段东西，两种做法都行：

- **选中的几行**：在编辑器里选中它 → **右键** → `DSH：把选中的代码带进对话`
  （没选中东西时这一项不出现）；
- **整个文件**：右键 → `DSH：把当前文件带进对话`。

东西会变成输入框上面的一小块（写着路径和"选中 N 行"），点小块上的 `×` 可以拿掉，
然后你接着打字提问、回车发出去。发出去之后，那条消息气泡里也留着当时带的东西 ——
回头翻记录能看出你当时指的是哪一段。

技术上的取舍（一句）：**选中的代码把正文直接给模型**（快、准），
**整个文件只给一条链接**，让 DSH 用它自己的工具去读 —— 大文件不占上下文，
读到的也永远是最新内容。这两条路都在真 DSH 上验过：我让它在"选中的代码"里
念暗号、在"带进来的文件"里读暗号，两次都答对了。

## 需要你知道的几件事
1. **测试在你的共享会话库里留下了一些会话记录。**
   我一条都没删 —— ACP 没有删除会话的接口，而且手删会话文件风险太高。
   如果你想让历史干净，我可以按时间和目录把它们筛出来，给你看过再删。
2. **门没有鉴权**，靠「只监听本机回环」兜底。正式用之前会加口令文件。
3. **权限弹窗你大概率看不到** —— 你的 desktop 档是 `auto-approval`，
   工具调用不会来问。改动的拦截方式我看的是事后 diff（面板里能看到改了什么）。
4. **模式（agent preset）能换了，但只在"新对话"上生效**：内核只允许
   「还没产出任何内容」的会话切预设（跑过回合就锁死）。所以面板里的模式下拉
   是**给下一段新对话用的**；如果你在一段已经说过话的对话里换，它会明确告诉你
   「已选 X：下一段新对话用它」，而不是假装生效了。
   四个模式就是桌面端那四个：标准 / PTC / 极简 / 创造。
5. 设置项都在 VS Code 设置里搜 `dshPanel`：地址、端口、自动拉起、兜底档、
   dsh 命令、初始服务商/模型、**模式**、工作目录。
6. **我重装扩展的时候 VS Code 正开着**，所以你现在这个窗口里可能还是旧版。
   如果看不到"把当前文件带进对话"这些新东西：`Ctrl+Shift+P` → `Developer: Reload Window`
   （或者干脆重启 VS Code）。
7. **"翻历史会话"这个功能我没做**，原因值得你知道：内核的 ACP 接口只给了
   `session/new`、`session/list`、`session/resume`、`session/close`、
   `session/set_config_option`、`session/prompt` 这一组（我读了它的源码逐个核过），
   **没有 `session/load`** —— 也就是说能列出来、能接着聊（上下文它记得），
   但**没法把那段对话的正文回放给面板**。我不想给你一个"点开是空白、但它记得"
   的半成品，所以留到有明确做法时再做（要么门自己读会话记录，
   要么你给我个别的偏好）。
8. **受限模式也支持了（今天凌晨刚修的真 bug）。** 之前这个扩展没有声明
   "支持不受信工作区"，于是**只要 VS Code 以受限模式打开文件夹，这个面板会被
   整个禁掉** —— 而且不报错，只是"图标/面板凭空不见了"。这是我开真窗口自检时
   抓到的：同一个扩展，不带工作区文件夹能激活，带一个未被信任的文件夹就完全不
   加载。现在清单里声明了 `capabilities.untrustedWorkspaces`，静态契约里也加了
   一条断言焊住它，不会再退化。
9. **"dsh 命令写错"这种错，现在一秒就说清楚，不用等两分钟。** 以前：门连不上
   → 自动拉起 → 命令不存在 → 进程立刻退出，但代码还在老老实实等满 120 秒的
   端口探测，你只看到"正在后台启动 DSH…"，两分钟后拿到一句"没开门"，还得自己
   猜为什么。现在盯着子进程：它一退出就马上告诉你"刚启动就退出了（命令：xxx），
   多半是 dsh 不在 PATH 里，或者 dshPanel.dshCommand 指错了 —— 先跑一次
   `dsh --version` 确认，再把完整路径填进设置"。面板层测试里钉了这条：
   用真进程跑，耗时必须小于 15 秒。
10. **兜底失败现在分两种说法（以前混成一句「没开门」）。** 一种是「后台 DSH 刚启动就
    退出了」——出路是查 dshCommand/PATH；另一种是「进程活着但端口一直没开」——出路是
    查那个档里有没有装门插件（`dsh plugin --profile desktop list` 应当能看到
    dsh-acp-door），以及门插件里的 port 有没有被改过。这两种说法的分支以前**从来没有
    测试覆盖**（正常跑要等满 120 秒），这轮给等待函数加了一个只有测试用的超时参数，
    现在几秒就能跑到 —— 面板层测试因此从 43 项涨到 50 项。

## 今晚的三次险情（都修好了，但你该知道）

我按你交代的"自己搞测试、自己迭代"在动，过程中有三次差点出事，都当场发现并修掉：

1. **门插件的源码目录被清空过一次。** 我为了图方便把测试档的依赖换成 `link:`
   （真符号链接），pnpm 清理时把链接指向的源码目录一起删了。救回来的方式：
   档里装的那份拷贝是完整的，拷回去 + 立刻备份 + 71 项测试确认没丢东西。
   教训已写进代码注释：**别用 `link:`**。
2. **桌面档的 `package.json` 被我写出过一个 BOM**（PowerShell 的 `-Encoding UTF8`
   会偷偷加），内核 `JSON.parse` 直接拒了 —— 那意味着你的桌面端起不来。
   当场用 Node 重写成无 BOM 并验证通过；现在那份文件是干净的。
3. **测试的同步逻辑差点改你的生产档。** 我用 `DSH_PANEL_PROFILE=desktop`
   在生产档上跑验证时，它顺手把桌面档的依赖从 `.tgz` 换成了源码目录。
   已恢复成 `.tgz`，并且改了规矩：**自动重装只允许动测试档**，
   生产档只检查、只报告。现在跑完都会核对"桌面档逐字节等于源码"。

## 性能这块做了什么

不是"感觉挺快"，是在真浏览器里量的（`node tools/uitest.js perf`）：

| 量什么 | 结果 |
| --- | --- |
| 117 个流式增量（约 2.3k 字）受理耗时 | < 1ms（攒批渲染，不是每个字都重排） |
| 落定（含渲染完 40 个 markdown 小节） | 远低于 1 秒 |
| 同样内容「流式喂」vs「一次喂完」的 DOM 规模 | 293 vs 290 个节点 |
| 尾巴有没有丢 | 没有（最后一片的内容在） |

最后那两行是这次新加的**回归护栏**：不管内容分多少片到达，渲染结果必须一样。
哪天有人把渲染改成"每个增量重渲染整棵树"，这两条会先炸。

## 出问题怎么办

- VS Code 里：`Ctrl+Shift+P` → `DSH：显示日志`，会打开输出通道 **DSH Panel**，
  连接、握手、建会话每一步都有记录。
- 还有两个命令：`DSH：新建对话`、`DSH：重新连接`。
- 想确认门在不在：`Test-NetConnection 127.0.0.1 -Port 47821`。
