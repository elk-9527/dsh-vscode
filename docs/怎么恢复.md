## 情况 A：代码被改乱了（最常见）

先看清楚动了什么，再决定丢多少：

```powershell
cd D:\dsh-vscode
git status                     # 哪些文件被改
git log --oneline -10          # workbuddy 提交了些什么
git diff v0.1-handoff --stat   # 相对恢复点改了多少
```

三种恢复力度，从小到大：

```powershell
# 1) 只丢掉"还没提交"的改动（已提交的提交都留着）
git checkout -- .

# 2) 保留 workbuddy 的提交当参考，但工作区回到恢复点
git branch workbuddy-试过的东西        # 先给它留个名字，不要直接丢
git reset --hard v0.1-handoff

# 3) 彻底回到恢复点，不看它做过什么（确认不需要它的提交时）
git reset --hard v0.1-handoff
git clean -fd                          # 顺手清掉它新增的未跟踪文件（会删文件，看清楚再执行）
```

**注意**：`reset --hard` 会丢掉未提交的改动，`git clean -fd` 会删掉未跟踪的文件。
执行前先 `git stash -u` 或者 `git branch` 留个名，别直接丢。

## 情况 B：`.git` 也没了（目录被删、被清空）

用备份单文件还原（这个文件里含全部历史与标签）：

```powershell
# 还原成一个新目录（推荐，不动现场）
git clone "D:\dsh-backups\handoff-20260917-1427\dsh-vscode-all.bundle" D:\dsh-vscode-restored
cd D:\dsh-vscode-restored
git checkout v0.1-handoff
git log --oneline -1        # 应当是 55e490f
```

还原出来的目录**不需要装任何依赖就能跑测试**：

- 扩展本体：`dependencies` 与 `devDependencies` 都是空的（零运行时依赖是刻意设计）；
- 界面测试：直接用系统里的 `C:\Program Files\Google\Chrome\Application\chrome.exe`，
  不用 puppeteer；
- 门插件：运行时依赖 `@agentclientprotocol/sdk` 已经装在桌面档的 `node_modules` 里，
  与仓库无关。

**唯一需要注意**：仓库根 `node_modules` 有 5 个包（不入库）。如果某个工具报缺包，
在仓库根跑一次安装即可（看清楚报的是什么包，不要盲目装一堆）。

## 情况 C：装进 VS Code 的扩展坏了 / 版本乱

源码在就直接重建，这是最干净的：

```powershell
cd D:\dsh-vscode\packages\vscode-extension
node tools/build-vsix.js
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension "build\dsh-panel-0.1.1.vsix" --force
# 版本号跟着 package.json 走（现在是 0.1.1），打包脚本自己按版本号命名
# 装完核一下"装进去的跟源码一致"（这个项目出过"改了源码但用户跑的还是旧版"）：
node D:\dsh-vscode\build\check-installed.cjs
```

懒得重建，就直接装备份里那个 vsix（按备份的日期挑最新的那个目录）：

```powershell
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension "D:\dsh-backups\handoff-20260919-0110\dsh-panel-0.1.1.vsix" --force
```

装完**必须**让 VS Code `Developer: Reload Window`（扩展是常驻的，不重载不生效）。

## 情况 D：桌面档（`$DSH_HOME\profiles\desktop`）被改坏了

这是**最需要小心**的一种（那里是用户在用的记忆与插件）。先判断坏成什么样：

```powershell
# 看桌面档的依赖清单（正常应当是 11 笔：10 个用户插件 + 1 个门插件 dsh-acp-door）
type "$env:USERPROFILE\.dsh\profiles\desktop\package.json"

# 与备份对照
Compare-Object (Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json") `
               (Get-Content "D:\dsh-backups\handoff-20260917-1427\desktop-profile-package.json")
```

- **只想撤掉门插件**（其他都不动）：
  ```powershell
  dsh plugin --profile desktop remove dsh-acp-door
  ```
- **门插件依赖行被改坏了**：把备份里的 `desktop-profile-package.json` 里的那一行
  `"dsh-acp-door": "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.7.tgz"`
  照原样写回去（**用编辑器/Node 写，不要用 `Set-Content`** —— 它会写 BOM，
  而 DSH 读带 BOM 的 `package.json` 会解析失败，这个坑踩过一次）。
- **整个档乱了**：用 `D:\dsh-vscode\backup\desktop-profile-20260917-003620`
  （门插件装上**之前**的快照）对照恢复 `package.json`；`node_modules` 不要整份覆盖
  （体积大、要重新装），只修 `package.json` 然后重装依赖。
- 恢复完**重启桌面端**让插件重新加载。

## 给接手方的三条硬要求（请照做）

1. **不要改写历史**：不要 `git commit --amend`、不要 `git rebase`、不要
   `git push --force`（现在没有远程，将来有了也一样）、不要删除或移动标签
   `v0.1-handoff`。发现做错了就**新加一个提交改回来**，或者在**新分支**上重做。
2. **每一步提交**，提交信息写清"解决了什么问题"。
3. **动手前先看一眼 `docs/交接文档.md` 里的硬规矩**，尤其是：
   不许改 `desktop` 档、不许删用户文件、不许按进程名杀 DSH 内核。
