## 情况 A：代码被改乱了（最常见）

先看清楚动了什么，再决定丢多少：

```powershell
cd D:\dsh-vscode
git status                     # 哪些文件被改
git log --oneline -10          # workbuddy 提交了些什么
git diff v0.1-handoff --stat   # 相对恢复点改了多少
```

三种恢复力度，从小到大：

```powershell
# 1) 只丢掉"还没提交"的改动（已提交的提交都留着）
git checkout -- .

# 2) 保留 workbuddy 的提交当参考，但工作区回到恢复点
git branch workbuddy-试过的东西        # 先给它留个名字，不要直接丢
git reset --hard v0.1-handoff

# 3) 彻底回到恢复点，不看它做过什么（确认不需要它的提交时）
git reset --hard v0.1-handoff
git clean -fd                          # 顺手清掉它新增的未跟踪文件（会删文件，看清楚再执行）
```

**注意**：`reset --hard` 会丢掉未提交的改动，`git clean -fd` 会删掉未跟踪的文件。
执行前先 `git stash -u` 或者 `git branch` 留个名，别直接丢。

   `v0.1-handoff`。发现做错了就**新加一个提交改回来**，或者在**新分支**上重做。
2. **每一步提交**，提交信息写清"解决了什么问题"。
3. **动手前先看一眼 `docs/交接文档.md` 里的硬规矩**，尤其是：
   不许改 `desktop` 档、不许删用户文件、不许按进程名杀 DSH 内核。
