状态是钉住的，一层一层说：

| 保险 | 位置 | 作用 |
| --- | --- | --- |
| git 标签 `v0.1-handoff` | 仓库内 | 一条命令回到这个提交（2026-09-17 的状态） |

| **整仓单文件备份（最新）** | `D:\dsh-backups\handoff-20260919-0944\` | **连 `.git` 一起没了也能还原**；2026-09-19 那一版（14 套件 949 项全绿、真编辑器三种情形各 11/11、HEAD `c71e3b2`） |
| 源码快照 `source-latest.zip` | 同上 | 不想用 git 时直接解压 |
| 装出来的东西 | 同上：`dsh-acp-door-0.0.9.tgz`、`dsh-panel-0.1.1.vsix` | 重建麻烦的两个产物 |
| 门插件的安装记录 | 同上：`desktop-profile-package.json`、`desktop-profile-cordis.patch.yml` | 桌面档被动过时对照恢复 |

| 更早（2026-09-17） | `D:\dsh-backups\handoff-20260917-1427\` | 里面是 `0.0.7.tgz` + `0.0.1.vsix`，更早的状态 |
| 装门之前的桌面档 | `D:\dsh-vscode\backup\desktop-profile-20260917-003620`、`...-020315` | 门插件装上**之前**的桌面档 |
| 上面那份的仓库外副本 | `D:\dsh-backups\handoff-20260919-0944\backup-装门之前的桌面档\` | 2026-09-19 起 `backup/` **不再进 git**（`.gitignore` 早就想忽略它，但早期加进去过的那 5 个文件一直在跟踪），所以仓库外留了一份 |

- **`backup/` 和 git 的关系**（2026-09-19 理顺）：`.gitignore` 里一直写着 `backup/`，
  但忽略规则**管不住已经被跟踪的文件** —— 最早加进去的 5 个文件还在版本控制里。
  现在用 `git rm -r --cached backup` 把它们摘出来了：**磁盘上一个文件都没少**，
  只是不再进 git。所以从 bundle 还原出来的仓库**没有** `backup/`，
  要那份桌面档就去上面表格最后一行那个路径拿。

- 标签 `v0.1-handoff` 指向提交 `55e490f`（"加交接文档与交接提示词"）。
- **2026-09-19 的那份备份**是在 14 个套件全绿、真编辑器自检 11 项全过之后打的，
  里面 `main` 的顶端是当时最后一次提交。**它做过还原演练**：
  `git clone <bundle>` 到一个空目录，能拿到完整的 138 个文件、HEAD 对得上。
- **期望的可用状态**：`node test/run-all.js --all` 全过（2026-09-19 实测
  **14 个套件、0 跳过**；自启内核那一套现在自己换空端口跑，不再因为桌面端开着而跳过）；
  `node tools/vscode-check.js` 11 项全过。
- **面板不需要桌面端在跑也能用**：端口上没有门时它自己启动内核（实测 5.2 秒可用）。
  这条是用户 2026-09-19 专门要求的，别退回"必须先开桌面端"的老文案。

**加完新东西之后，自己把备份刷新一下**（一条命令，几秒钟）：

```powershell
cd D:\dsh-vscode
# 写进一个**新日期**的目录，别覆盖上一份（上一份是上一个"已知好状态"的证据）
$dest = "D:\dsh-backups\handoff-$(Get-Date -Format yyyyMMdd-HHmm)"
New-Item -ItemType Directory -Path $dest -Force | Out-Null
# 只备份分支和标签：不要用 --all，那会把 DSH 自己的 refs/dsh-turn-rewind/*
# 临时快照引用（几十个）也打进去，白白撑大备份文件。
git bundle create "$dest\dsh-vscode-all.bundle" main v0.1-handoff pre-takeover
git bundle verify "$dest\dsh-vscode-all.bundle"           # 看到 complete history 就对了
git archive -o "$dest\source-latest.zip" HEAD             # 源码快照
# 再把两个"重建麻烦"的产物和桌面档的记录一起放进去：
Copy-Item packages\dsh-door\dsh-acp-door-0.0.9.tgz $dest   # 版本号跟着门源码走
Copy-Item packages\vscode-extension\build\dsh-panel-0.1.1.vsix $dest
Copy-Item $env:USERPROFILE\.dsh\profiles\desktop\package.json "$dest\desktop-profile-package.json"
# 面板自己那个档的清单也带上（它不在仓库里，重建要照着它看装了哪 11 个包）
Copy-Item $env:USERPROFILE\.dsh\profiles\vscode-panel\package.json "$dest\vscode-panel-profile-package.json"
# 最好再演练一次"能不能还原"（几秒钟，值得）：
git clone --quiet "$dest\dsh-vscode-all.bundle" D:\dsh-temp\restore-check; git -C D:\dsh-temp\restore-check log --oneline -1
```

## 情况 A：代码被改乱了（最常见）

先看清楚动了什么，再决定丢多少：

```powershell
cd D:\dsh-vscode
git status                     # 哪些文件被改
git log --oneline -10          # workbuddy 提交了些什么
git diff v0.1-handoff --stat   # 相对恢复点改了多少
```

三种恢复力度，从小到大：

```powershell
# 1) 只丢掉"还没提交"的改动（已提交的提交都留着）
git checkout -- .

# 2) 保留 workbuddy 的提交当参考，但工作区回到恢复点
git branch workbuddy-试过的东西        # 先给它留个名字，不要直接丢
git reset --hard v0.1-handoff

# 3) 彻底回到恢复点，不看它做过什么（确认不需要它的提交时）
git reset --hard v0.1-handoff
git clean -fd                          # 顺手清掉它新增的未跟踪文件（会删文件，看清楚再执行）
```

**注意**：`reset --hard` 会丢掉未提交的改动，`git clean -fd` 会删掉未跟踪的文件。
执行前先 `git stash -u` 或者 `git branch` 留个名，别直接丢。

## 情况 B：`.git` 也没了（目录被删、被清空）

用备份单文件还原（这个文件里含全部历史与标签）：

```powershell
# 还原成一个新目录（推荐，不动现场）
git clone "D:\dsh-backups\handoff-20260917-1427\dsh-vscode-all.bundle" D:\dsh-vscode-restored
cd D:\dsh-vscode-restored
git checkout v0.1-handoff
git log --oneline -1        # 应当是 55e490f
```

还原出来的目录**不需要装任何依赖就能跑测试**：

- 扩展本体：`dependencies` 与 `devDependencies` 都是空的（零运行时依赖是刻意设计）；
- 界面测试：直接用系统里的 `C:\Program Files\Google\Chrome\Application\chrome.exe`，
  不用 puppeteer；
- 门插件：运行时依赖 `@agentclientprotocol/sdk` 已经装在桌面档的 `node_modules` 里，
  与仓库无关。

**唯一需要注意**：仓库根 `node_modules` 有 5 个包（不入库）。如果某个工具报缺包，
在仓库根跑一次安装即可（看清楚报的是什么包，不要盲目装一堆）。

## 情况 C：装进 VS Code 的扩展坏了 / 版本乱

源码在就直接重建，这是最干净的：

```powershell
cd D:\dsh-vscode\packages\vscode-extension
node tools/build-vsix.js
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension "build\dsh-panel-0.1.1.vsix" --force
# 版本号跟着 package.json 走（现在是 0.1.1），打包脚本自己按版本号命名
# 装完核一下"装进去的跟源码一致"（这个项目出过"改了源码但用户跑的还是旧版"）：
node tools/check-installed.cjs
```

懒得重建，就直接装备份里那个 vsix（按备份的日期挑最新的那个目录）：

```powershell
& "D:\Microsoft VS Code\bin\code.cmd" --install-extension "D:\dsh-backups\handoff-20260919-0944\dsh-panel-0.1.1.vsix" --force
```

装完**必须**让 VS Code `Developer: Reload Window`（扩展是常驻的，不重载不生效）。

## 情况 D：面板自己的档（`$DSH_HOME\profiles\vscode-panel`）没了或被改坏

这个档**不在仓库里**，是 2026-09-19 在用户机器上建的（面板自己启动内核时用它）。
它坏了或换机器了，照下面三条重建 —— 一分钟的事：

```powershell
# 1) 从官方 web 模板建（一定要 web 模板：ACP 那种档不接受 --host/--port，门没法开 TCP）
dsh --profile vscode-panel --from-default-profile web --dump-config | Out-Null

# 2) 把门装进去（版本号跟着 packages/dsh-door 里的 tgz 走）
dsh plugin --profile vscode-panel add "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.9.tgz"

# 3) 想要"和桌面端一样的那套插件"就再装一遍（可选；不装就是个干净内核）
dsh plugin --profile vscode-panel add `
  "@anionex/dsh-turn-rewind@0.3.8" "@changfenhuang/dsh-genui@0.11.0" `
  "@linxin666/dsh-client-ui-skin-center@0.3.23" "@liustack/modlens@3.26.1" `
  "@liustack/modsearch@5.10.3" "@tt-a1i/archify-dsh@0.1.0" `
  "dsh-auto-approval-plugin@2.1.2" "dsh-better-sidebar@0.19.1" `
  "dsh-context@0.52.2" "dshmarket@1.47.0"

# 4) 起一次确认门能开（它会一直跑着，看到门就 Ctrl+C）
dsh --profile vscode-panel --no-open --host 127.0.0.1 --port 0
```

判断"这个档能不能被面板用"，看两条：`dsh --profile vscode-panel --help` 里有
`--host/--no-open/--port`（说明是网页档），`dsh plugin --profile vscode-panel list`
里有 `dsh-acp-door`（说明装了门）。面板起不来时也会自己在 `$DSH_HOME/profiles` 里
找这样的档当备选。

## 情况 E：桌面档（`$DSH_HOME\profiles\desktop`）被改坏了

这是**最需要小心**的一种（那里是用户在用的记忆与插件）。先判断坏成什么样：

```powershell
# 看桌面档的依赖清单（正常应当是 11 笔：10 个用户插件 + 1 个门插件 dsh-acp-door）
type "$env:USERPROFILE\.dsh\profiles\desktop\package.json"

# 与备份对照
Compare-Object (Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json") `
               (Get-Content "D:\dsh-backups\handoff-20260917-1427\desktop-profile-package.json")
```

- **只想撤掉门插件**（其他都不动）：
  ```powershell
  dsh plugin --profile desktop remove dsh-acp-door
  ```
- **门插件依赖行被改坏了**：把备份里的 `desktop-profile-package.json` 里的那一行
  `"dsh-acp-door": "file:D:/dsh-vscode/packages/dsh-door/dsh-acp-door-0.0.7.tgz"`
  照原样写回去（**用编辑器/Node 写，不要用 `Set-Content`** —— 它会写 BOM，
  而 DSH 读带 BOM 的 `package.json` 会解析失败，这个坑踩过一次）。
- **整个档乱了**：用 `D:\dsh-vscode\backup\desktop-profile-20260917-003620`
  （门插件装上**之前**的快照）对照恢复 `package.json`；`node_modules` 不要整份覆盖
  （体积大、要重新装），只修 `package.json` 然后重装依赖。
- 恢复完**重启桌面端**让插件重新加载。

## 给接手方的三条硬要求（请照做）

1. **不要改写历史**：不要 `git commit --amend`、不要 `git rebase`、不要
   `git push --force`（现在没有远程，将来有了也一样）、不要删除或移动标签
   `v0.1-handoff`。发现做错了就**新加一个提交改回来**，或者在**新分支**上重做。
2. **每一步提交**，提交信息写清"解决了什么问题"。
3. **动手前先看一眼 `docs/交接文档.md` 里的硬规矩**，尤其是：
   不许改 `desktop` 档、不许删用户文件、不许按进程名杀 DSH 内核。
