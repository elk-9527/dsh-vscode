## 一、这个东西是什么，要达成什么

**一句话**：在 VS Code 的侧边栏里用你自己那套 DSH —— 不是另一个 agent，
而是同一个内核（同一份 `$DSH_HOME`、同一份记忆、同一套技能/插件、同一份会话记录），
只是不显示前台窗口。

**原始目标的五个子项**（照抄自任务书）：

1. 连接层：能连上 DSH「门」；端口上没有门时**自己启动一个内核**
   （共用同一份 `$DSH_HOME`，因此同一份记忆与会话记录）——
   **不要求用户先打开桌面端**（用户 2026-09-19 专门强调过这一条）。
2. 侧边栏面板能完整对话：流式输出、工具调用展示、中断、模型/预设切换、上下文用量。
3. 自建测试与迭代循环，反复找 bug → 修 → 重测，直到稳定。
4. 装进 VS Code 并端到端验证通过。
5. 再做 UI 与性能优化。

**硬约束**（来自用户，务必遵守）：

- **绝不修改桌面端的 `desktop` profile**（那里的记忆/插件是用户在用的）。
  唯一允许的例外已经做完了：装了一个门插件（见下），并且知道怎么卸。
- 不删除用户的文件。
- 不破坏现有编译环境。
- 每完成一步提交 git。
- 用户不喜欢比喻、要"说人话"；不明确的地方**先问**，不要自己拍脑袋。

## 二、架构（三段式，理解它就能改任何地方）

```
VS Code 侧边栏（扩展 UI：webview）
      │  ACP：JSON-RPC，一行一个 JSON（NDJSON）
      ▼
  「门」插件 dsh-acp-door（装在 DSH 内核里的插件，在本机回环再挂一份 ACP 桥）
      │  默认监听 127.0.0.1:47821
      ▼
  正在运行的 DSH 内核（用户的桌面端，或者扩展自己拉起的无窗口内核）
```

**为什么要门这个东西**：DSH 内核本体不对外提供 ACP（它是给编辑器用的协议），
所以用一个内核插件在回环地址上再开一份 ACP。门**只监听回环、没有鉴权**
（这是一个已知的、需要向用户披露的安全边界：本机任何进程都能连上那个端口）。

**两种运行模式**（用户明确关心过，2026-09-19 重新表述过一次）：

- 端口上**已经有门**（桌面端在跑）→ 面板直接接入它：一个进程、一个大脑，
  不会再多起一个内核。
- 端口上**没有门**（桌面端没开、刚开机）→ 面板自己启动一个**无窗口**内核
  （`dsh --profile <档> --no-open --host 127.0.0.1 --port 0`），连它干活，
  关掉 VS Code 时**收掉自己拉的那个**（桌面端那个绝不碰）。

所以**用这个插件不需要先打开桌面端**。这不是"兜底"，是**主路径之一**：
实测（2026-09-19，桌面端同时开着、测试自己挑 47830 端口）从零到可以提问
**5.2 秒**，握手、建会话、跑一个真回合、收摊杀干净全部通过；
**真 VS Code 隔离窗口里也验过**（13 项全过，11 秒建出会话；Stage A/B 之后
`DSH_PANEL_CHECK_LINGER=60` 那一轮同样 13/13；2026-09-19 夜加了权限那条断言之后
是 **15 项全过**）—— 见下面 `vscode-check` 那段。

> **措辞红线**（用户 2026-09-19 为此专门提过意见）：界面文案里**不许**出现
> "已连上正在运行的 DSH""桌面端没在跑…"这种把桌面端说成前提的话。
> 空态文案现在写的是"内核由插件自己按需启动，不用先去桌面上打开 DSH"。
> 将来改文案时请守住这一条。

### 界面约定（2026-09-19 定的，别再改回去）

- **顶栏那一行只放短状态**：`正在连接…` / `正在启动…` / `就绪` / `工作中…` / `未连接`。
  它是一条很窄的行，塞长句子会把工作目录、耗时挤掉。`media/main.js` 的
  `shortStatus()` 还有一道防守：万一长文案走到 status，也只显示第一行并截到 24 字。
- **报错进对话流**（`{type:'error'}` → `.msg-error`），不进顶栏。用户的说法是
  "像其他 agent 那样把报错写在对话框"。长原文收在 `<details>原始报错（点开）</details>` 里：
  **一个字都不删**，但不摊在脸上。认不出来的错误（没有人话标题）例外 —— 原文就是唯一信息，
  必须直接摊开。
- **"正在启动内核"这类解释**走 `{type:'notice'}`（对话流里那条居中的系统提示），
  不占顶栏。

**曾经确认过的一个硬限制（2026-09-17 已绕过）**：内核的 ACP 接口只提供
`initialize / authenticate / session/new / session/list / session/resume / session/close /
session/set_config_option / session/prompt` 和通知 `session/cancel`。
**没有 `session/load`** —— 意思是能列会话、能 resume（上下文能接回），但**没法把
历史对话的正文回放给面板**。绕过办法（用户 2026-09-17 已点头）：**门自己读
`$DSH_HOME/sessions`**（多帧 zstd 解码 + 回放重建，纯函数库在 `packages/dsh-door/lib/sessions.js`，
门 0.0.8 起以 `dsh-door/sessions/list|get` 两个旁路方法对外提供，请求由门就地应答、不转发内核）。

**14. `fallback.js` 现在会自己换个空端口跑**（`DSH_PANEL_TEST_PORT=47830`，
`run-all.js` 里给这一套单独设了 env）。所以**桌面端开着也能跑**，
不再是"环境不满足就跳过"。

> 2026-09-19 之前它是硬要求 47821 空着的，于是桌面端一开就必然跳过 ——
> 而"自启内核"恰恰是用户最常走的那条路（刚开机、没开桌面端）。
> 现在端口可换，这条路每次全量测试都会被真跑一遍（9.6 秒）。
> 换端口的做法：给内核挂一个 `--patch`，把门那一行的 `port` 钉过去。
> **注意门那一行的 `config` 是整段替换的**（实测：只写 `port`，`host`/`provider`/
> `model`/`preset` 会一起消失），所以 patch 里必须把每个字段都写全 ——
> 见 `test/fallback.js` 的 `writeDoorPortPatch()`。
>
> 这个套件还验了「**复用**」：连上之后掐断客户端连接、再发一条消息 ——
> 必须接着用原来那个内核（pid 不变、没有第二个进程），而不是每连一次就多起一个。
> 那种 bug 在界面上看不出来（照样能用），只会在进程列表里越堆越多。

## 2026-09-19 补记：`desktop` 档起不来这件事（用户报的 bug，已修）

**症状**：用户 Reload Window 之后，面板报「没能启动 DSH 内核」，档是 `desktop`，
建议他去改 `dshPanel.dshCommand`。

**真因（查清楚了，不是猜的）**：

1. `desktop` 这个档**被桌面端独占**，普通命令行起不来。它自己会明说：
   `error: profile "desktop" is managed exclusively by the Electron application`。
   而它恰好是当时的默认值 —— 所以"桌面端没开"时面板必然起不来，
   而那正是最需要它自己起来的时候。
2. PATH 上那个 `dsh` 是**桌面端自己的垫片**：
   `set ELECTRON_RUN_AS_NODE=1 & "DSH Desktop.exe" --expose-internals .../desktop-cli.js %*`。
   它**能**跑 `desktop` 档。但它住在
   `…\host-commands\desktop\generations\<哈希>\bin\` 这种一次性目录里，
   桌面端换代就换路径 —— 一个开得早的 VS Code 进程 PATH 里可能还指着
   已经删掉的那一代。于是 `dsh` 找不到、`node bin.js` 又拒绝 `desktop`，
   **两条候选一起死**，就是用户看到的那两条失败。
3. 面板当时还把内核的 stderr 扔了（`stdio: 'ignore'`），所以报错是**猜**的
   （"多半是 dsh 不在 PATH 里"）—— 用户按那句话去改 dshCommand 只会越改越远。

**修法**：

- 面板有了自己的档 **`vscode-panel`**：
  `dsh --profile vscode-panel --from-default-profile web`（官方 web 模板 → 命令行能起、
  能开 TCP 门），再 `dsh plugin --profile vscode-panel add <门 tgz>` 和用户那 10 个插件。
  默认 `dshPanel.fallbackProfile` 改成它。
- **起不来就换档**：`panelProfileCandidates()` 扫 `$DSH_HOME/profiles`，挑出
  "装了 `dsh-acp-door` 且有 `@deepseek-ai/dsh-web-app`"的档当备选（设置里那个永远第一）。
- **不再扔 stderr**：末尾 2000 字留着，`explainKernelFailure()` 认得出
  "档被独占 / 参数不对 / 命令找不到 / 端口被占"，认得出来就照实说，认不出来才回退到猜，
  而且原话一字不删地附在后头。
- 复现这件事的测试：`test/fallback.js` 第 5 节 + `test/static.js` 的候选档/退出原因那几项。

**用户机器上留下的东西**（仓库外，重建方法见 `docs/怎么恢复.md`）：
`$DSH_HOME/profiles/vscode-panel/`；`$DSH_HOME/profiles/vscode/` 里多装了门插件
（那个档是 ACP-stdio 用的，门对它没用，但装着无害），改之前留了
`package.json.before-door.bak` / `cordis.yml.before-door.bak`。

### 第二步（Stage A）：内核归扩展，不归面板视图

以前 `dispose()` 里直接 `killTree` 自己起的那个内核。而**视图比你以为的容易没**：
折叠侧边栏、拖面板、`Reload Window`、另一个窗口关掉……每一次都是一次"杀内核 + 重连"。
用户看到的"聊两句突然断线"完全可以是这么来的。

新代码 `src/panel/kernel-manager.js`：内核按 `host:port` 登记，记使用者集合。

- 面板**用**内核 → `acquire`；面板销毁 → `release`（**只松手，不杀**）；
- 最后一个使用者松手 → 进宽限（`dshPanel.kernelIdleMinutes`，默认 10 分钟，
  设 0 = 老行为"一关就收"）→ 到期才收；
- 宽限期内面板重开 → **继续用同一个进程**（日志：`面板又用上这个后台 DSH 了，
  原本要收它的计时取消`）；
- **窗口关闭**（`deactivate`）和 **「DSH：停掉后台内核」**（新命令）→ 无条件收；
- 别人起的（桌面端那个）**永远不碰**：没登记的内核，`release` 不会误杀任何东西。

### 第三步（Stage B）：端口归起内核的人定

以前面板自启的内核也用 47821 —— 那正是**桌面端那个内核的端口**。两个内核抢同一个
端口没有任何好处，抢输的那个门干脆不开，用户对着"正在启动…"干等。

- 新设置 `dshPanel.selfStartPort`（默认 **47831**）：面板自启的内核把门钉在这儿。
- 门的判定顺序（`packages/dsh-door/lib/port.js`，纯函数 + 8 项单测）：
  **环境变量 `DSH_ACP_DOOR_PORT` > 档里配的 `port` > 默认 47821**。
  扩展启动内核时把这个变量写进去（`spawnBackgroundDsh({port})`）。
- **旧版门兼容**（必须的，用户的档里当时是 0.0.9/0.0.7，它们不认这个变量）：
  自启之后面板**两个端口都盯**（`[selfStartPort, port]`），哪个门开了用哪个。
- `dshPanel.port`（47821）的含义变清楚了：**"去接谁"**，默认接桌面端那个内核；
  自启不用它。
- 门升到 **0.0.11** 并装进 `vscode-panel` 档（0.0.10 那个包**带 BOM，装上去会让
  `dsh plugin` 直接崩** —— 见 `docs/机器上被我改过什么.md`）。

## 八、踩过的坑（照抄，别再踩）

1. **`build/` 会被打包脚本清空**：`node tools/build-vsix.js` 会 `rmSync(build)`。
   想留下的产物别放 `build/`（截图就因为这个丢过一次，现在放 `shots/`）。
2. **绝不用名字去 `taskkill` 内核**：用户自己的 DSH Desktop 拉起的内核命令行里
   也有 `--no-open`，跟扩展拉起的长得像。自检工具现在**一个内核都不杀**，
   只收自己开的隔离窗口，剩下的只报告（并排除"祖先是 DSH Desktop.exe"的进程）。
3. **扩展拉起的内核长这样**：`cmd.exe /d /s /c "dsh --profile desktop --no-open
   --host 127.0.0.1 --port 0"`；真正的 `DSH Desktop.exe` 子进程命令行里反而**没有**
   `--profile/--no-open`。要识别"是不是我们拉起的"，认那个 `cmd.exe`。
4. **无头 Chrome 不为程序化滚动派发 scroll 事件（实测 0 次）**。界面的
   "别把正在翻记录的人拽回底部"逻辑靠 scroll 事件判断，直接测会得出假 bug。
   `tools/uitest.js` 里是**手动派发**一个 scroll 事件来测，注释写清了原因。
5. **`tools/uitest.js` 里的断言脚本是模板字符串**：注释和代码里都不能出现反引号，
   换行必须写 `\\n`，否则生成出来的脚本直接语法错。
6. **PowerShell 引号/编码**：内联 `node -e` 写中文、`$()`、反引号极易被吞。
   写脚本或提交信息一律**用文件**（`git commit -F 文件`）。
   **而且：改文件不要用 PowerShell 的 `Set-Content -Encoding UTF8`** ——
   它会给文件加 UTF-8 BOM（`EF BB BF`）。2026-09-19 我就这么把门包的
   `package.json` 加了 BOM，打进 tgz、装进用户的档，结果 `dsh plugin` 每次
   都崩在 `JSON.parse`（`Unexpected token '﻿'`）——等于把人家那个档搞坏了。
   改文件用编辑工具；`node tools/check-eol.cjs` 会报 BOM，
   `test/static.js` 里也有一条断言焊着（查装机文件）。
   顺带一个坑：`pnpm` 的 lockfile 记的是 tgz 的完整性哈希，
   **把已装过的 tgz 删掉/换内容**会让 `pnpm add` 直接报 `ENOENT` ——
   要么先补回那个文件，要么换版本号。
7. **`code.cmd` 会把参数转给正在运行的实例**，不能用来开隔离窗口。要开隔离窗口必须
   直接起 `Code.exe`，带 `--user-data-dir` / `--extensions-dir` / `--new-window` /
   `--verbose`（没有 `--verbose` 时输出通道日志不落盘）。
8. **切换模型必须信内核回复**（`setSessionConfigOption` 返回的 `configOptions`），
   不能信自己请求的值 —— 内核会归一化。
9. **预设（agent preset）**：只有桌面端创建的会话会把 preset 写进会话记录；
   走门建的会话需要请求里带 `_meta['dsh-door']` 补挂，否则**恢复回来的会话没有工具**。
10. **`dsh` 命令不在 PATH 时**以前要干等 120 秒才报错。现在盯子进程：
    它一退出就立刻说清"命令错了、怎么办"。这条分支的测试覆盖率是靠给等待函数
    加一个只有测试用的超时参数才做到的。
11. **`$pid` 是 PowerShell 只读变量**，循环里别用它当变量名。
12. **`dshCommand` 里带参数会起不来**（2026-09-17 修）。`locate.js` 原来把**整串**
    命令当一个程序名加引号，于是 `node D:\...\bin.js` 变成 cmd 眼里「名字里有空格的
    程序」，退出码 1。现在先 `splitCommand()` 拆再逐段加引号。
13. **本机 `dsh` 命令不在 PATH 上**。npm / pnpm / nvm 的 bin 目录里都没有 `dsh.cmd`，
    唯一的 CLI 是 `C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js`
    （v0.1.5-rc.2）。所以：
    - 扩展自启内核时要把 `dshPanel.dshCommand` 填成
      `node C:\Users\Lenovo\.dsh\profiles\node_modules\@deepseek-ai\dsh\lib\bin.js`；
    - 命令行跑需要真内核的测试时，先设
      `$env:DSH_PANEL_DSH = "<那个 node.exe 的完整路径> <bin.js 的完整路径>"`；
    - 不设的话，`panel.js` / `smoke.js` / `fallback.js` 这些会失败（**不是代码坏了**）。
14. **worktree 的换行符和主工作区不一致**。`D:\dsh-vscode` 工作区里的文件是 LF
    （上一轮用写文件工具写的），而新开的 worktree 按 `core.autocrlf=true` 检出成
    CRLF。git 会归一化所以两边 `git status` 看着都干净，但
    `test/helpers/door.js` 的 `doorDrift()` 是**逐字节比对** —— 在 worktree 里它会
    误报「门跟源码不一致」，然后试图用 `dsh plugin` 重装（再撞上第 13 条）。
    碰上门相关测试前先把 `packages/dsh-door/**` 统一成 LF。另外 `dshdoor` 测试档
    的门依赖指向的是 `D:/dsh-vscode/packages/dsh-door`，不是 worktree。
15. **沙箱会拦 pnpm 的批量删除**（2026-09-17 踩过）。`syncDoor()` 的 remove+add
    会触发 pnpm 换依赖文件，一换超过阈值（实测 184 个文件、阈值 50）就被
    `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 拦下 —— add 失败且**测试档
    的 `package.json` 依赖已被 remove 清空**，内核启动时不再加载门（症状：
    内核起来了、47821 永远不开）。`syncDoor()` 现在对 add 失败有兜底（按文件
    同步 lib + 手工补回依赖声明）。真要重装：先把旧依赖目录**改名挪开**再 add，
    pnpm 就不需要删东西，能成功。
16. **`probePort` 是单次探测，`waitForPort` 才是等门开的**。门要 10~40 秒才开，
    用 `probePort` 判断「门开没开」几乎必然假阴性（它只试一次，连接被拒就
    返回 false）。等门一律 `waitForPort(host, port, { totalMs })`。
17. **TransformStream 没人消费 readable 就整条管子是死的**（2026-09-17 踩过，
    门 0.0.8 曾因此哑掉）。出站中继最初写成 TransformStream 却没人读
    `relay.readable` —— transform 永远不执行，内核回复永远出不去，客户端
    看到的是「门接了线但不应答」。现在出站层是 `frames.js` 的
    `createOutboundRelay()`（返回 WritableStream，ndJsonStream 直接写它），
    并且有「写进来的行必须从 sink 出来」的测试盯着（`test/frames.js` 第 8 节）。
18. **`dsh` CLI 不许动 desktop 档**（2026-09-18 实测）：`dsh plugin --profile desktop
    remove/add` 直接被拒（`profile "desktop" is managed exclusively by the Electron
    application`）。升门只能手动改文件（做法见第七节第 4 条）。
19. **GNU tar 把 `D:` 当远程主机**：Windows 盘符路径（`tar -xzf D:/...`）报
    `Cannot connect to D: resolve failed`。路径写成 `/d/...` 就好。
20. **`dsh plugin --profile desktop …` 只在桌面端**没跑**时能用**（2026-09-18 实测）：
    桌面端跑着的时候，CLI 直接拒（`profile "desktop" is managed exclusively by the
    Electron application`）。09-17 那次装门之所以成功，是因为当时桌面端没开。
    所以"升级桌面档的门"这件事不能想当然，见第七节第 4 条。
21. **`spawn(cmd.exe, [...])` 会把参数里的引号再转义一遍**（2026-09-19 修，真 bug）。
    Windows 上要跑 `cmd.exe /d /s /c "完整命令行"` 时，如果字符串里已经带了引号
    （比如程序路径里有空格，你把它括起来了），默认的 spawn 会再转义一次，cmd 收到
    的就变成了坏掉的路径。必须同时给 `windowsVerbatimArguments: true`。
    另一个独立的坑：**不能只按空白拆命令**。本机 dsh 的真路径是
    `…\AppData\Roaming\DSH Desktop\host-commands\…\dsh.cmd`，路径里**有空格**，
    用户按说明"把完整路径填进设置"填的是裸路径，按空白拆会把程序名劈成两段，
    报的错是 `'C:\Users\…\Roaming\DSH' is not recognized as an internal or external
    command`（这是 cmd 的原话；面板会翻成中文人话）。
    **注意**：cmd 的输出语言跟着它的环境走 —— 用脚本 spawn 出来时这台机器给的是
    英文，而面板自己那条中文文案是**翻译**（`src/dsh/errors.js` 两种都认）。
    所以别照着"中文原文"去搜日志。
    现在 `resolveCommand()` 会「优先认整串是一个存在的文件」，再退到
    「把拆坏的片段按磁盘上真实存在的路径重新粘回去」（`rejoinExisting`）。
    回归测试：`test/spawn-quote.js`（16 项，**真进程**）—— 它造一个带空格的
    `.cmd` 垫片，用真的 `spawnBackgroundDsh()` / `runDshSync()` 去跑，
    再读垫片的输出对内容。为什么必须真跑：这两个缺陷拼出来的字符串**看起来是
    完全正确的**，只断言 `commandLine()` 的返回值抓不住。这个套件在
    `run-all.js` 里，不需要 dsh、不占端口。
22. **同一个方法名被复用时，测试的断言会悄悄变成在验另一件事**（2026-09-19 修，
    真 bug）。`DoorClient.listSessions()` 本来是 ACP 的 `session/list`（返回
    `{sessionId, cwd}`），被改成走门的旁路方法（返回 `{id, title, turns}`）之后，
    `test/smoke.js` 里那段"验 ACP 列表形状"的**注释和断言都没跟着改** ——
    于是门一旧它就以一个和被测代码无关的理由变红。现在两个方法名字分开了：
    `listKernelSessions()` 是 ACP 的，`listHistory()`/`getHistory()` 是门的。
23. **两份实现必须有一条一致性测试拴着**（2026-09-19）。历史会话读取现在有两份
    （门 ESM 一份、面板 CJS 一份，因为扩展零依赖、不能 require 门的 ESM）。
    光靠"注释里写一句要同步"是拦不住的，所以有 `test/sessions-parity.js`：
    同一批会话文件喂给两份，44 项逐项比对，包括坏帧、截断、非法 id、缺目录。
24. **失败路径上的状态不清会污染下一次**（2026-09-19 修，真 bug）。
    `decorateLine()` 的预筛写着 `line.includes('"result"')`，于是**只有 error、
    没有 result** 的回复压根没被看：`state.queue` 里那条点名永远不清理。它是按
    "发出顺序"领的（`session/new` 时 sessionId 还不知道），于是**下一次**建会话
    会领到上一次失败时点的那个预设 —— 用户没点名却挂上了别的模式。
    修法：出错回复也要处理（把点名从队列里摘掉）。回归测试在
    `test/frames.js` 第 8 节第 (6) 段。
25. **"等一个 promise"必须有上限，否则故障是"消息静默消失"**（2026-09-19 修）。
    入站闸 `holdUntilMounted()` 原来是 `await waiting.catch(() => {})`，
    没有超时。挂载链内部全都 catch 过，唯一漏网的是内核某个服务返回**永不落定**
    的 promise —— 那时 `session/prompt` 被永久按住：用户发了消息，界面上没有任何
    反应，也没有任何报错可查。现在入站和出站用同一个上限（`MOUNT_WAIT_MS`，
    通过 `frames.js` 的 `waitForMount()`），到点放行，最坏退化成"这个会话手里没工具"。
26. **PowerShell 5.1 的 `Get-Content -Raw` 会把 UTF-8 读成乱码**，`ConvertFrom-Json`
    跟着解析失败（2026-09-19 连踩两次）。读 JSON 一律用 Node（`JSON.parse(fs.readFileSync)`），
    别用 PowerShell 的 JSON 命令。同理：内联 `node -e "…"` 里的引号/反引号极易被
    PowerShell 吞掉 —— **写成 `.cjs` 文件再跑**（临时脚本放 `build/`，它不入库）。

## 九、自检工具的口径（别把它当成"万能")

- `test/*` 大多用假客户端/假 vscode，快但不覆盖"人能不能找到入口"这种真机问题。
- `tools/vscode-check.js` 用 `DSH_PANEL_AUTOFOCUS=1` 让扩展**自己**打开面板，
  所以它验证了"激活 → 展开 → 握手 → 建会话"整条链，但**恰好绕过了"用户点得到吗"**。
  这正是早上出问题的地方：**自动化通过 ≠ 人能用**。人机交互环节最好也让用户试一次。
- 断言自己也要被验证：曾经有一条"消息间距一致"的检查写成"≥3 条消息才检查"，
  而场景里只有 2 条 —— 从来没跑过（死代码）。
