## 原始参考（量出来的现状，改前改后都用得上）

### 一条硬约束：跟随 VS Code 主题

面板长在 VS Code 侧边栏里，旁边就是编辑器。所以颜色**一律用主题变量**
（`--vscode-*`），不自己定死颜色 —— 否则你换个主题，面板就成了那块"贴歪的膏药"。
这条现在是达标的：审计过 404 条 CSS 声明，**硬编码颜色 0 处**，用了 32 个主题变量。

颜色所以不是主要问题；**主要问题是尺寸尺度**。

## 量出来的现状（`node tools/design-audit.js`，可随时复跑）

| 项 | 现状 | 问题 |
| --- | --- | --- |
| 间距值 | 10 种：1 / 2 / 3 / 4 / 5 / 6 / 8 / 10 / 12 / 20 px | 6 种不在 4px 尺度上，是随手写的 |
| 字号 | **13 种**：0.82 / 0.85 / 0.9 / 0.92 / 0.94 / 0.95 / 1.05 em，10 / 11 / 13 px，1em，inherit，主题字号 | 0.9/0.92/0.94/0.95 挤在一起，等于"没有层级" |
| 行高 | 5 种：1 / 1.45 / 1.5 / 1.55 / 1.6 | 1.45/1.5/1.55/1.6 之间的差别肉眼看不出来 |
| 圆角 | 4 种：2 / 3 / 4 / 999px | 这个还算合理（层级 + 胶囊） |

**"看着不够精致"的根源就在这张表里**：不是颜色不对，是尺寸没有尺度 ——
13 种字号意味着每个元素各自调了一次，凑出来的整齐是偶然的。
另外：只用过一次的间距值是 1px / 5px / 20px，这几个最像"当时觉得差一点，随手加的"。

## 原提案（用户默认认可：不改配色、不改布局结构，只把尺度收敛）

不改配色、不改布局结构，只把尺度收敛：

- **字号收敛成 4 档**（现在 13 种）：正文（跟主题字号）、次要信息（0.92em）、
  标题（1.05em）、代码（0.9em 等宽）。层级靠**字重**区分，不靠再加一档字号。
- **间距收敛到 4px 尺度**（4 / 8 / 12 / 20）：1px、2px、3px 这类只剩描边和
  行内微调才用；5px、6px、10px 归到 4 或 8。
- **行高收敛成 2 档**：正文 1.55、紧凑处（卡片标题、状态行）1.35。

预期效果：元素之间"看起来有关系"，而不是各自为政。改完 `design-audit` 的
数字会直接显示收敛结果，`tools/shots.js` 也能给出前后对比图。

## 原 6 问原文（存档备查，答案见文首表格）

1. **品牌感要不要**：面板要不要有一点自己的识别度（比如顶栏一条细的强调色、
   或某处一个固定的强调色），还是完全交给主题、一点自己的颜色都不加？
   —— 这是"看着像 VS Code 自带功能"和"看着像一个有主人的工具"的分界。
2. **消息形态**：现在是你/它的两栏对话。要更像聊天（有气泡、有头像），
   还是更像"文档流"（像现在这样，它的话就是正文，工具调用是折叠卡片）？
3. **工具调用的显示**：现在是一张张卡片、默认展开。要不要默认折叠成一行
   （"读了 3 个文件 ▸"），点开才展开？对话长了以后这个差别很大。
4. **密度**：你自己的偏好 —— 是"一屏能看更多"（紧凑），还是"留白多一点"（松弛）？
5. **动效**：要不要一点克制动效（新消息淡入、工具卡片展开收起有过渡）？
   现在基本没有动效。
6. **信息的取舍**：现在顶栏是模型 + 上下文用量，右上角是新建/重连。要加时间戳、
   花费/耗时、当前工作目录吗？还是越干净越好？

改的顺序：先定尺度 → 再定形态 → 最后每处细节；每步都拍图，不满意就回退。
